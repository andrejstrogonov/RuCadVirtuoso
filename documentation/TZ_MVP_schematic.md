| Поле | Значение |
|---|---|
| Документ | ТЗ на минимально жизнеспособный продукт (MVP) |
| Область | Только схемотехническая часть (schematic + simulation) |
| Версия | 1.0 (черновик) |
| Продукт | RuCadVirtuoso — кастомная САПР, совместимая по идеологии с Cadence Virtuoso |

## 1. Термины и сокращения

| Термин | Расшифровка |
|---|---|
| MNA | Modified Nodal Analysis — узловой анализ с модификацией |
| DAQ | Differential-Algebraic Equation — дифференциально-алгебраическая система уравнений |
| Netlist | Текстовое описание схемы списком соединений |
| VA | Verilog-A (аналоговое подмножество Verilog-AMS LRM 2.4.0) |
| OSDI | Open Source Device Interface — ABI загрузки скомпилированных моделей |
| DC / TRAN / AC | Анализы: рабочая точка, переходный процесс, малосигнальный частотный |
| RS | Resistive Switching — резистивное переключение |
| TS | Threshold Switching — пороговое (энергонезависимое/энергозависимое) переключение |
| SV | State Variable — внутренняя переменная состояния прибора |
| Мемтранзистор | Трёхвыводной прибор: мемристивное состояние канала, управляемое затвором |
| Нейристор | Двухвыводной пороговый прибор с энергозависимым переключением, основа интегрирующего нейрона |

---

## 2. Цель и назначение MVP

Создать настольное приложение, позволяющее инженеру:

1. Собрать схему из примитивов (R, C, L, источники, управляемые источники) и приборов (MOSFET, мемристор, мемтранзистор, нейристор).
2. Задать модели приборов либо параметрами встроенных моделей, либо собственным Verilog-A файлом.
3. Выполнить анализ DC / TRAN / AC и увидеть результаты в виде графиков и таблиц.
4. Сохранить проект и воспроизвести результат на другой машине.

MVP должен давать численно достоверный результат (сверка с ngspice в пределах допусков п. 12), а не только демонстрацию интерфейса.

**Не входит в MVP (см. п. 16):** layout, DRC/LVS, экстракция паразитов, цифровое моделирование, mixed-signal, шумовой анализ, Monte-Carlo, оптимизация, RF/S-параметры, гармонический баланс, совместная работа, Pcell-генерация топологии.

---

## 3. Пользователи и сценарии

**Основной пользователь:** инженер-схемотехник / исследователь мемристивной электроники, знакомый с SPICE-подобными инструментами.

**Сценарий S1. Проверка ВАХ мемристора.**
Пользователь создаёт схему «источник напряжения — мемристор — земля», задаёт параметры модели Yakopcic, запускает TRAN с треугольным сигналом, наблюдает петлю гистерезиса I(V) и траекторию SV x(t).

**Сценарий S2. Импорт собственной модели.**
Пользователь пишет `my_rram.va`, импортирует его через диалог «Import Verilog-A», видит, что модель скомпилирована, размещает символ прибора на схеме, задаёт параметры через форму, запускает DC-развёртку.

**Сценарий S3. Нейристорный нейрон.**
Пользователь собирает LIF-нейрон: нейристор + конденсатор + резистор + источник импульсов; запускает TRAN; видит генерацию спайков и частоту как функцию входного тока.

**Сценарий S4. Кроссбар-массив.**
Пользователь описывает массив 4×4 мемристоров на уровне netlist (иерархия через subckt), запускает TRAN, наблюдает токи по столбцам.

## 4. Границы MVP и определения готовности

### 4.1 Входит в MVP

| Блок | Состав |
|---|---|
| Ядро | Парсер собственного формата схемы (SPICE-совместимый синтаксис + расширения), построение MNA-системы, решатель DC/TRAN/AC |
| Verilog-A | Транслятор VA → C++, компиляция в DLL, загрузка через ctypes, извлечение матрицы проводимостей и заряд-токов |
| Библиотека приборов | MOSFET (упрощённая компактная модель), мемристор (2 модели), мемтранзистор (GEM-подобная), нейристор (2 модели: пороговая и гистерезисная) |
| Редактор схем | Размещение элементов, соединение, иерархия, символы, свойства, netlist-listing |
| Анализы | OP (рабочая точка), DC-sweep, TRAN (BDF1/TRAP + фиксированный/переменный шаг), AC (малосигнальный) |
| Результаты | Просмотрщик графиков (встроенный), экспорт CSV |
| Хранение | Проект-каталог: `.rcad` (схема), `.rlib` (библиотека моделей), `.va` (исходники), кэш скомпилированных DLL |
| Инсталляция | Inno Setup, self-contained Python-дистрибуция |

### 4.2 Не входит в MVP

Layout/DRC/LVS, температурный анализ сверх одной температуры по умолчанию, шумовой анализ (`.noise`), Monte-Carlo/угловые прогоны, оптимизатор, DC-инкрементальный, PZ, TF, S-параметры, Harmonic Balance, поведенческие цифровые блоки, Verilog-AMS digital, `$display`/`$fopen` (см. п. 8.6), бинарный VCD-формат, сетевой режим.

### 4.3 Критерии готовности MVP (Definition of Done)

MVP считается готовым, если одновременно выполнены все пункты:

1. Все функциональные требования п. 6–11 реализованы, кроме явно помеченных «опционально».
2. Тесты п. 12 проходят в CI (headless) на Windows.
3. Время симуляции кроссбара 16×16 мемристоров на 10 000 точек TRAN — не более 120 с на эталонной машине (п. 13).
4. Ни один пользовательский .va файл не приводит к падению приложения: ошибки компиляции и выполнения показываются в UI и логируются.
5. Установщик ставит приложение на чистую Windows без установленного Python и компилятора (для встроенных моделей).

## 6. Формат проекта и netlist

### 6.1 Формат хранения схемы

Проект — каталог `<project>.rcad/`:

```
<project>.rcad/
  project.json        # метаданные: имя, версия формата, библиотеки
  cells/<cell>.json   # схемы (иерархия по cell)
  symbols/<cell>.json # символьные представления (опционально; по умолчанию авто)
  models/<name>.json  # параметры встроенных моделей (.model)
  veriloga/<file>.va  # исходники моделей
  cache/              # скомпилированные DLL и метаданные (не в VCS)
```

Схема (`cells/<cell>.json`) содержит: список инстансов (имя, мастер-ячейка, параметры), координаты, поворот/зеркало, список соединений (net-имена, привязки к портам), список портов ячейки, свойства ячейки.

### 6.2 Netlist (текстовый формат)

Схема должна экспортироваться/импортироваться в текстовый SPICE-совместимый netlist:

```
* комментарий
.include "models/memristor_yakopcic.lib"
.options reltol=1e-4 abstol=1e-12 vntol=1e-6 maxstep=1e-9 gmin=1e-12

.subckt mem_cell top bot
M1 top gate bot 0 nmos_1u W=2u L=0.18u
Xmem top bot memristor_yakopcic a1=0.17 a2=0.17 b=0.05 Vp=0.65 Vn=0.56
.ends

X1 in 0 mem_cell
V1 in 0 sin(0 1 1k)
.tran 1u 1m
.end
```

**Требования к парсеру:**
- Поддержка: `.model`, `.subckt/.ends`, `.include`, `.options`, `.ic`, `.param`, `.tran/.dc/.ac/.op`, `.end`.
- Продолжение строки `+`, регистронезависимость ключевых слов и имён узлов, комментарии `*` и `;`, номера узлов `0`/`gnd` эквивалентны.
- Имена узлов: буквы/цифры/`_`/`#`/`.` (иерархические `X1.N3`).
- Единые суффиксы величин: `f p n u m k meg g t`, а также `1e-9`-нотация; ошибки формата — сообщение с номером строки.
- `.param` с выражениями над числами и другими параметрами (арифметика, `+ - * / ( ) , **`, функции `sqrt exp ln log sin cos tanh min max abs pow`).
- Иерархия: `X<name> <nodes...> <subckt> [param=val ...]`, рекурсивное разворачивание с сохранением пути узла.

**Ошибки парсера** возвращаются структурно: `{file, line, column, code, message}`; при ошибке симуляция не запускается, но проект остаётся валидным.

## 7. Ядро моделирования

### 7.1 Построение системы (MNA + DAE)

Форма системы — заряд/поток-ориентированная (charge/flux formulation), чтобы корректно работать с нелинейными ёмкостями мемристивных приборов:

```
f(x) = d/dt q(x) + i(x) + u = 0
```

где `x` — вектор неизвестных (узловые напряжения + токи через источники напряжения/индуктивности), `q(x)` — вектор зарядов на ёмкостях и потоках, `i(x)` — вектор резистивных токов и вклад источников тока, `u` — вклад независимых источников.

Требования:

1. Сборка разреженной структуры (CSR) выполняется **однократно** на этапе компиляции схемы; численные значения обновляются на каждой итерации.
2. Каждый прибор предоставляет вклад в:
   - `i_el` и матрицу `G = ∂i/∂v` (статическая часть),
   - `q_el` и матрицу `C = ∂q/∂v` (динамическая часть),
   - опционально шум (в MVP не используется),
   - опционально внутренние переменные (см. 7.3).
3. Сингулярность, отсутствие пути к земле для узла, висящий вывод — диагностируются до решения (проверка: каждый узел имеет хотя бы одно DC-соединение к земле; каждый источник напряжения не образует контур из источников напряжения/индуктивностей).
4. Опция `gmin`: шунтирование каждого узла проводимостью `gmin` к земле (по умолчанию 1e-12 См) для избежания сингулярности.

### 7.2 Матрица Якобиана: аналитика или конечные разности

- Встроенные модели обязаны предоставлять **аналитический Якобиан** (проверяется тестом на соответствие конечным разностям с точностью 1e-6).
- Модели Verilog-A: генератор кода по умолчанию строит аналитические производные (символьное дифференцирование AST через дублирование выражений); при наличии неподдерживаемой конструкции — падение на конечные разности и warning в лог.
- Разностная аппроксимация: центральные разности, шаг `h = 1e-8 · max(|v|, 1)`.

### 7.3 Внутренние переменные приборов (state variables)

Мемристивные приборы требуют внутренних дифференциальных уравнений (`dx/dt = f(x, v, t)`), задаваемых автором модели.

Требования:

1. Прибор объявляет произвольное количество внутренних переменных состояния `x_i`, каждая — со своим начальным значением (`initial`).
2. Внутренние переменные добавляются к глобальному вектору неизвестных как «виртуальные узлы» с уравнениями невязки `F_i = dx_i/dt - f_i(x, v) = 0`.
3. Для численной устойчивости в точке интегрирования дискретизация `dx_i/dt` выполняется той же формулой, что и для ёмкостей (п. 7.5), т.е. `x` интегрируется как заряд.
4. Ограничение состояния: прибор обязан реализовать ограничение (`x ∈ [xmin, xmax]`) внутри `f_i`; ядро не обрезает `x` молча, но фиксирует в логе выход за границы как `W_STATE_CLIP` при включённом режиме отладки.
5. Внутренние переменные доступны для **прямого вывода в результаты** (по имени, напр. `@Xmem.x`) — это критично для отладки мемристивных моделей.

### 7.4 Решатель нелинейной системы

1. Метод Ньютона–Рафсона с модифицированной матрицей (обновление Якобиана при расходимости).
2. Критерий сходимости: `|Δx| < reltol·|x| + abstol` по напряжениям (`vntol`, по умолчанию 1e-6 В) и `abstol` для токов, `reltol` по умолчанию 1e-4.
3. Максимум итераций — 100, при недостижении — `ConvergenceError` с указанием узла с наибольшей невязкой.
4. Стратегии повышения устойчивости (реализуются по порядку):
   - `gmin`-stepping (постепенное уменьшение шунта);
   - демпфирование шага (`dV = λ·Δx`, λ = 1 → 0.1 при расходимости);
   - `source stepping` для DC-анализа;
   - переключение на `pseudo-transient` как последний резерв (для DC и OP).
5. Линеаризация разреженной системы — SciPy `splu` (или `spsolve`), допускается замена на `KLU` при обосновании по производительности.

### 7.5 Интегрирование по времени (TRAN)

1. Поддерживаемые методы:
   - **BDF1 / Backward Euler** — обязательный, используется для старта и как резерв;
   - **TRAP (trapezoidal)** — по умолчанию;
   - **BDF2** — опционально, если TRAP даёт звон при переключениях (достаточно TRAP + control шага).
2. Управление шагом: локальная оценка ошибки LTE по методу встроенной производной, `reltol`/`abstol` управляют шагом; `maxstep` — жёстко ограничен (по умолчанию `(tstop-tstart)/100`, настраивается).
3. Обработка разрывов: источники `PULSE`/`PWL` объявляют точки разрыва; интегратор **обязан** попасть точно в эти точки (не «перепрыгивать» фронт).
4. Обязательна поддержка «непрерывного» продолжения: результат доступен как интерполируемые ряды по времени с исходными точками интегрирования.
5. Отклик на неудачу сходимости: уменьшение шага вдвое до `minstep`; при исчерпании — останов с указанием времени и узла.

### 7.6 DC и OP

- DC-sweep: развёртка напряжения/тока независимого источника, один или два (вложенных) параметра; первый параметр — внешний цикл.
- Режим `OP`: рабочая точка в t=0 для TRAN и самостоятельный анализ.
- Обязательная проверка: решения DC непрерывны — при разрыве (переключение мемристора) выдаётся предупреждение `W_DC_DISCONTINUITY`.

### 7.7 AC (малосигнальный)

1. Линеаризация в найденной рабочей точке DC; построение комплексной системы `(G + jωC)·v = b`.
2. Поддерживаемые варианты развёртки: `dec`, `oct`, `lin` с указанием точек/декоду.
3. Тип развёртки — по частоте (основной) и по параметру (опционально).
4. Выход: комплексные векторы узловых напряжений и токов; модуль/фаза в dB/deg.

### 7.8 Единицы и масштабы

- Внутренние единицы — СИ (В, А, Кл, Гн, Ф, Ом, См, А/В, К). Суффиксы netlist применяются в парсере.
- Температура: `$temperature` (или `TEMP`) — в Кельвинах, по умолчанию 300.15 К; задаётся `.options temp=` глобально.

## 8. Поддержка Verilog-A (обязательный блок)

### 8.1 Общая схема работы

1. Пользователь импортирует `.va` через UI («Import Verilog-A» → выбор файла или каталога).
2. Валидация расширения: файл проверяется на наличие ровно одного `module` и блока `analog`.
3. Транслятор строит AST, проверяет типы, генерирует C++-исходник.
4. Компиляция: `cl.exe` (MSVC) → DLL, размещение в `cache/<hash>.dll`; хэш — SHA-256 от содержимого `.va` и версии транслятора.
5. Загрузка: `ctypes.CDLL`, получение структуры описания модели.
6. Метаданные (порты, параметры с типами/значениями/диапазонами, имя, версия) извлекаются и используются для построения символа и формы параметров.

### 8.2 Поддерживаемое подмножество Verilog-A (MVP)

**Обязательно:**

| Категория | Состав |
|---|---|
| Модуль | `module name(port_list); ... endmodule` |
| Порты | `inout`, `input`, `output` (все электрические — `electrical`/`wire`); привязка `V(p,n)`, `I(p,n)` |
| Параметры | `parameter real x = 1e-9 from (0:inf);` — `real`, `integer`; `from` проверяется |
| Локальные переменные | `real`, `integer`; массивы `real name[0:N]` (N — константа) |
| Аналоговый блок | `analog begin ... end` (единственный) |
| Операторы | присваивание, `if/else`, `case`, `while`, `for`, `repeat`, блок `begin/end`, `+ - * / ** %`, сравнения, `&& || !`, тернарный `?:` |
| Встроенные функции | `abs, min, max, sqrt, exp, ln, log10, sin, cos, tan, asin, acos, atan, sinh, cosh, tanh, asinh, acosh, atanh, pow, floor, ceil, limes`, а также `V(), I()` |
| Преобразование | `ddt(expr)`, `ddt(expr, abshdl)`, `idt(expr)`, `idt(expr, ic)`, `ddx(...)`, `white_noise(...)` — **только для стубов** (см. 8.4) |
| Вклады | `I(p,n) <+ expr;`, `V(p,n) <+ expr;`, `I(p,n) <+ ddt(expr);`, `I(p,n) <+ idt(expr);` |
| Напряжение | `V(p,n)` — чтение, `$temperature`, `$vt`, `$simparam`, `$param_given`, `$port_connected` (ограниченно) |
| Сообщения | `$strobe`, `$display`, `$warning`, `$error`, `$fatal` — вывод в консоль приложения |
| Начальные условия | `@(initial_step)`, `@(final_step for analysis)`, `@(analysis("tran"))` (см. 8.5) |

**Не поддерживается в MVP (сообщение об ошибке с указанием конструкции):**

- digital-часть Verilog-AMS, `always`, конечные автоматы, `event`;
- `discontinuity()`, `bound_step()`, `analog function`, `task`/`function` пользовательские определения;
- `laplace_nd/laplace_zp/zi_*`, `slew`, `transition`, `$limit`/`$bound_step` (в MVP — ошибка трансляции; альтернатива: предэкспортный хинт параметров `smooth`);
- `generate`, `genvar`, `analog initial`, `@(cross)`/`@(above)`;
- access-функции по свободным ветвям (`I(p,n)` для ветви без источника — только через `I(<source>)`), `V(p,n)` с производными по времени (`ddt(V)` разрешено);
- `$random`, `$dist_*`.

### 8.3 Семантика derivative и операторов

- `ddt(e)` внутри `I(p,n) <+ ...` — вклад в `q`; `dt(e)` внутри `q` — ошибка трансляции.
- `idt(e)` допустимо только для вспомогательных переменных и для формирования внутренних состояний; внутри `I(...)` превращается во внутреннюю переменную, уравнение которой `dx/dt = e`.
- Производные `ddx(e, V(a,b))` и `∂I/∂V` не поддерживаются в MVP (ошибка трансляции с рекомендацией записать через `V` и параметры).
- Параметр, помеченный `from (...)`, валидируется; выход за диапазон — ошибка времени выполнения `VA_PARAM_RANGE`.

### 8.4 Генерация кода и API загружаемой модели

Транслятор генерирует C++ со следующими обязательными точками входа (стабильный ABI, `extern "C"`):

```c
typedef struct {
  const char* name;
  int         num_terminals;
  int         num_params;
  int         num_internal_states;
  /* параметры, порты, метаданные — массивы дескрипторов */
} va_model_info;

int  va_eval_static (const double* v, const double* p, const double* t,
                     double* i_el, double* gmat);           /* резистивный вклад */
int  va_eval_dynamic(const double* v, const double* p, const double* t,
                     double* q_el, double* cmat);           /* ёмкостный вклад  */
int  va_eval_state  (const double* v, const double* p, const double* x,
                     double* dx);                           /* внутренние состояния */
int  va_init        (double* state, const double* p);       /* initial_step */
const va_model_info* va_get_info(void);
```

Требования:
- `i_el`, `q_el`, `dx` вычисляются с точностью double.
- `gmat`/`cmat` — плотные `n×n` (n = терминалы), с аналитическими производными.
- Ошибки: возвращаемое значение != 0, текст ошибки — через `va_get_error()`.
- ABI документируется и версионируется (`VA_ABI_VERSION`); при несовпадении — DLL не загружается.

### 8.5 События и анализ-специфика

- `initial_step`: вызывается один раз перед первым шагом каждого анализа; инициализирует SV и рабочие векторы параметров.
- `analysis("dc"|"tran"|"ac")`: фильтр активности; в остальных — блок пропускается.
- `final_step`: вызывается после последней точки, `$strobe` печатается в лог.

### 8.6 Ограничения и поведение при ошибках

| Ситуация | Требуемое поведение |
|---|---|
| Синтаксическая ошибка .va | Ошибка трансляции с `file:line:col`, текст в UI; DLL не создаётся |
| Конструкция вне подмножества | Явное сообщение «not supported in MVP» с именем конструкции |
| Нет компилятора MSVC | Диалог с инструкцией; можно указать путь к `cl.exe` в настройках |
| Ошибка компиляции C++ | Лог компилятора в файл, ссылка из UI |
| DLL устарела (изменён .va) | Автоматическая перекомпиляция по хэшу |
| Ошибка в модели во время симуляции | Симуляция останавливается, `VA_RUNTIME_ERROR` с именами модели и прибора |

## 9. Библиотека приборов

Каждая модель обязана: иметь символ, список параметров с метаданными (имя, тип, значение по умолчанию, диапазон, единица), аналитический Якобиан, тестовый netlist-эталон и набор эталонных кривых (golden-данные).

### 9.1 MOSFET (микроэлектронный транзистор)

**Назначение:** базовый 4-терминальный прибор (D, G, S, B) для сборки управляющих схем.

**Модель MVP:** упрощённая компактная модель уровня Shichman-Hodges + учёт эффекта тела (body effect) и канал-модуляции.

Требования:
- Области: отсечка, линейная, насыщение; плавный переход между ними (без разрывов в Якобиане).
- Параметры: `W, L` (инстанс), `VTO, KP, GAMMA, PHI, LAMBDA, TOX, CGSO, CGDO, CGBO, RD, RS` (модель).
- Ёмкости: `Cgs, Cgd, Cgb` с разбиением по области, в которой находится прибор.
- Ток утечки подпорогового режима — минимум: экспоненциальная добавка `ISUB` (без полноценного BSIM).
- Целевая проверка: совпадение с ручным расчётом для 3 областей (допуск 1e-3).
- **Не требуется:** BSIM4/PSP, шум, mismatch, NQS, температура сверх `temp`-зависимости mobility.

### 9.2 Мемристор

**Модель M1 — Yakopcic (по умолчанию, 2 терминала + опционально третий узел SV).**

Полная дискретизация из опубликованной модели (эталонный SPICE subckt, используется как golden):

```
G(V) = 0,                           -Vn <= V <= Vp
     = Ap·(exp(V)  - exp(Vp)),      V >  Vp
     = -An·(exp(-V) - exp(Vn)),     V < -Vn
F(V,x) = exp(-αp·(x-xp))·wp(x),     η·V >= 0, x > xp
       = 1,                          иначе
       = exp(αn·(x+xn-1))·wn(x),    η·V <  0, x < 1-xn
       = 1,                          иначе
wp(x) = xp/(1-xp) - x/(1-xp) + 1
wn(x) = x/(1-xn)
dx/dt = η·F(V,x)·G(V)
I     = a1·x·sinh(b·V),             V >= 0
      = a2·x·sinh(b·V),                      V < 0
```

Параметры: `a1, a2, b, Vp, Vn, Ap, An, xp, xn, alphap, alphan, xo, eta`.
SV: `x ∈ [0, 1]`, начальное `xo`.
Требования: ограничение `x` в окне (`x=xp` при росте, `x=1-xn` при спаде) реализуется внутри `F`, `x` не выходит за `[0,1]`; при `η=-1` — инверсное поведение.

**Модель M2 — линейный ионный дрейф (HP/Lin) — упрощённая, для быстрых проверок.**

```
R(x) = R_on·x + R_off·(1-x)
dx/dt = μv·R_on/D² · I
```

Параметры: `Ron, Roff, D, mu_v, x0`. Предупреждение в документации: модель не имеет порога и используется для базовой сверки.

**Модель M3 — VTEAM (опционально):** пороговая модель с двумя окнами; реализуется только в Verilog-A внутри репозитория моделей (не как нативное C++), чтобы в MVP проверить сквозной сценарий S2.

### 9.3 Мемтранзистор (3 терминала: D, G, S)

**Модель MVP — GEM (GEneral Memristive transistor) в поведенческой форме.**

Требования:
- Внутреннее состояние `w`, управляемое напряжением затвор-исток `vgs`.
- Дифференциальное уравнение состояния:

```
dw/dt = a_off·(exp(vgs - v_off) - 1) + β_off·(w_off - w)^s_off,  vgs < v_off
      = 0,                                                       v_off <= vgs <= v_on
      = a_on·(exp(vgs - v_on) - 1)  + β_on·(w - w_on)^s_on,      vgs > v_on
```

  (точные выражения — реализация уравнений (1)–(3) из публикации GEM; коэффициенты `k_off, k_on, α_off, α_on, s_off, s_on, β_off, β_on, v_off, v_on` — параметры);
- Функция «окна монотонности»: `g_off(w, vgs)`, `g_on(w, vgs)` ограничивают диапазон `w` в зависимости от амплитуды `vgs` (выражения (2)–(3) источника);
- Выходные характеристики `ids(vds, vgs, w)` — нелинейная функция с двумя режимами («линейный»/«насыщение») и зависимостью `R_M(w)` (по умолчанию `R_M(w) = R_on·w/w_on + R_off·(1 - w/w_on)`);
- Терминал G не потребляет постоянного тока (кроме ёмкости `Cgs`, опционально).

Параметры (минимально обязательные): `w_on, w_off, k_on, k_off, alpha_on, alpha_off, s_on, s_off, beta_on, beta_off, v_on, v_off, r_on, r_off, mu, w_init`.
Требования: `w` ограничено в `[w_off, w_on]`; при недостаточной амплитуде `vgs` (ниже порога) `w` не меняется; тест на «стробоскопическое» поведение — 1 импульс `vgs` даёт ожидаемое изменение `w` и `ids`.

### 9.4 Нейристор

**Модель N1 — порогово-переключающая (volatile TS) — обязательная.**

Двухтерминальный прибор с энергозависимым переключением:

```
состояние s ∈ {HRS, LRS}
переход HRS→LRS: |V| >= V_threshold  (или V >= V_set)
переход LRS→HRS: |V| <= V_hold       (спонтанный возврат, время τ_relax)
R = R_off (HRS) | R_on (LRS)
```

Параметры: `R_on, R_off, V_set, V_hold, t_delay, t_relax, C_par`.

**Модель N2 — гистерезисная (энергонезависимая, с плавным переходом) — обязательная.**

Плавная пороговая модель с внутренним состоянием `s`, непрерывным при `V_set` (для корректной работы Ньютона):

```
ds/dt = (1/τ)·(σ(|V| - V_set) - s),   s ∈ [0, 1]
R(s)  = R_off·(1-s) + R_on·s
```

Параметры: `R_on, R_off, V_set, V_hold, tau_set, tau_relax, s_init, sigma`.

**Требования к обеим моделям N1/N2:**
- Работоспособность в LIF-нейроне: нейристор + параллельный конденсатор `C` + токовый вход; на TRAN должен наблюдаться периодический спайковый отклик, частота которого монотонно растёт с входным током (тест п. 12).
- Отсутствие «дребезга»: переключение за один шаг без многократных рестартов интегратора; для N1 обязательна гладкая аппроксимация ступеньки (сигмоида с шириной `V_smooth`, скрытой от пользователя) с настраиваемой шириной.

### 9.5 Примитивы (обязательные)

R, C, L, независимые источники V/I (`DC`, `SIN`, `PULSE`, `PWL`, `AC magnitude/phase`), управляемые источники `E` (VCVS), `G` (VCCS), `F` (CCCS), `H` (CCVS), зависимые поведенческие `B` (только `V = expr`/`I = expr`, с выражением над узловыми напряжениями) — **опционально**, если время позволяет.

## 16. Риски и решения

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Численная неустойчивость мемристивных моделей (жёсткие уравнения, переключения) | Высокая | Высокое | Мягкие ступеньки/сигмоиды в моделях, BDF + контроль шага, `maxstep` по умолчанию, `pseudo-transient` резерв; тест T13 |
| Verilog-A транслятор выходит за рамки MVP | Средняя | Высокое | Жёсткое подмножество п. 8.2 + явные ошибки вместо частичной поддержки; fallback — `ddt`/`idt` только, без `ddx` |
| Отсутствие MSVC у пользователя | Высокая | Среднее | Встроенные модели — нативные (не требуют компилятора); MSVC нужен только для VA; опциональный шаг инсталлятора |
| Отличие результатов от опубликованных моделей | Средняя | Высокое | Golden-эталоны от ngspice/референсных subckt; запрет на «подгонку» моделей под тесты |
| Производительность Python на кроссбарах | Средняя | Среднее | Разреженная сборка однократно, SciPy `splu`, векторизация на NumPy, профилирование на E1; при провале — замена решателя на KLU через `scikit-sparse`/Cython (закладывается архитектурно) |
| Нейристор не даёт стабильных спайков | Средняя | Среднее | Обе модели N1/N2, настраиваемая ширина порога, тест T8 как гейт |

## 17. Открытые вопросы (требуют решения заказчика)

1. Нужен ли экспорт/импорт **SPICE-netlist** в MVP как «контракт» совместимости (сейчас — «да, только текстовый, импорт упрощённо»), или достаточно собственного формата?
2. Требуется ли совместимость с существующими моделями BSIM4 (тогда — внедрение OSDI/OpenVAF как альтернативы собственному транслятору, что меняет объём E2)?
3. Нужна ли поддержка `.va` моделей, использующих `$limit`/`bound_step` (практически необходима для качественных TS-моделей; в текущем подмножестве — ошибка)?
4. Нужен ли в MVP **multi-physics** учёт температуры/джоулева разогрева для нейристоров (энергозависимое переключение часто требует тепловой подмодели)?
5. Степень детализации MOSFET: достаточно ли Shichman-Hodges-уровня для заявленных «микроэлектронных транзисторов», или с первого релиза нужен субмикронный уровень?
