# Требования ISTQB: библиотека приборов RuCadVirtuoso (MVP)

| Поле | Значение |
|---|---|
| Документ | Формализованные требования, часть «Библиотека приборов» |
| Источник | `documentation/TZ_MVP_schematic.md`, разделы 9 (9.1–9.5), 12.1, 12.2, приложение B |
| Область | Контракт модели прибора, MOSFET, мемристор M1/M2/M3, мемтранзистор GEM, нейристор N1/N2, примитивы |

## 1. Соглашения

### 1.1 Идентификаторы

`FR-<БЛОК>-<NNN>` — функциональное требование, `NFR-<БЛОК>-<NNN>` — нефункциональное.

| Блок | Содержание |
|---|---|
| `DEV` | общий контракт модели прибора (ТЗ п. 9, вводный абзац) |
| `MOS` | MOSFET (ТЗ 9.1) |
| `MEM` | мемристор M1 Yakopcic (ТЗ 9.2) |
| `MEM2` | мемристор M2 линейный дрейф (ТЗ 9.2) |
| `MEM3` | мемристор M3 VTEAM, опционально (ТЗ 9.2) |
| `MT` | мемтранзистор GEM (ТЗ 9.3) |
| `N1` / `N2` | нейристор N1 / N2 (ТЗ 9.4) |
| `NR` | общие требования к N1/N2 и LIF-нейрону (ТЗ 9.4) |
| `PRIM` | примитивы (ТЗ 9.5) |

### 1.2 Приоритеты (MoSCoW)

| Приоритет | Правило присвоения |
|---|---|
| Must | в ТЗ помечено «обязательно» / «обязательная» / «**обязательные**» |
| Should | обязательный прибор, у которого в ТЗ ограничена детализация («минимум», «упрощённая») либо допустим отказ при заданном условии |
| Could | в ТЗ помечено «опционально» / «если время позволяет» |

### 1.3 Уровни тестирования (ТЗ 12.1)

| Метка | Уровень |
|---|---|
| U | Unit — Якобиан, уравнения модели, ограничения состояния |
| G | Golden — сверка с ngspice/эталонным subckt, допуск `reltol=1e-3, abstol=1e-9` (ТЗ 12.1) |
| I | Integration — сквозные сценарии S1–S4 |
| S | UI smoke |
| P | Производительность/приёмка (ТЗ 4.3, 13) |

Тест-кейсы T4–T8, T13 берутся из ТЗ 12.2 без изменения нумерации; Link T13 в таблице трассировки означает, что требование проверяется внутри кроссбар-прогона T13 (здесь — пункт «без разрывов в SV»).

## 2. Общий контракт модели прибора

Источник: вводный абзац п. 9 ТЗ.

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-DEV-001 | Каждая модель прибора поставляется с символом для размещения на схеме | Must | В панели библиотеки доступны символы всех моделей приложения B; размещение даёт инстанс |
| FR-DEV-002 | Каждая модель предоставляет список параметров с метаданными: имя, тип, значение по умолчанию, диапазон, единица | Must | Для каждой модели метаданные полны по перечню параметров своего блока; параметр без метаданных — дефект |
| FR-DEV-003 | Каждая модель предоставляет аналитический Якобиан (`G = ∂i/∂v`, `C = ∂q/∂v`) | Must | Сверка с центральными разностями (`h = 1e-8·max(|v|,1)`) по всем терминалам, точность 1e-6 (ТЗ 7.2) |
| FR-DEV-004 | Каждая модель поставляется с эталонным netlist-ом для запуска без UI | Must | Netlist запускается через headless API `run_analysis` и завершается без ошибок |
| FR-DEV-005 | Каждая модель поставляется с набором эталонных кривых (golden-данные в `tests/golden/`) | Must | Файл CSV присутствует в репозитории; повторный прогон воспроизводит его в допуске G |
| FR-DEV-006 | Наличие эталонных данных не позволяет «подгонять» модель под тест: правка golden-файла под модель запрещена | Must | Ревью: изменение golden-файла в PR допускается только вместе со ссылкой на источник эталона (ТЗ 16) |
| FR-DEV-007 | Внутренние переменные состояния доступны для прямого вывода в результаты по имени (`@inst.x`) | Must | В списке выводимых величин доступен SV каждого прибора; ряд присутствует в Result (ТЗ 7.3 п.5) |
| FR-DEV-008 | Выход значения SV за объявленные границы фиксируется в логе как `W_STATE_CLIP` при включённом режиме отладки; ядро не обрезает SV молча | Must | При искусственном нарушении границ в модели запись `W_STATE_CLIP` присутствует в логе только в debug-режиме (ТЗ 7.3 п.4) |
| NFR-DEV-001 | Модель не падает на граничных значениях параметров: выход за диапазон `from (...)` даёт `VA_PARAM_RANGE`, нативная модель — диагностику с именем прибора | Must | Прогон с параметром на границе и за границей: получено сообщение, приложение живо (ТЗ 4.3 п.4) |
| NFR-DEV-002 | Сверка с ngspice для каждого прибора выполняется в CI и использует единый допуск `reltol=1e-3, abstol=1e-9` | Must | Golden-тест зелёный в CI; ослабление допуска в тесте отсутствует (ТЗ 12.1) |

## 3. MOSFET (ТЗ 9.1)

Терминалы: D, G, S, B (4). Тип: n и p (приложение B).

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-MOS-001 | Прибор имеет 4 терминала D, G, S, B; реализованы n- и p-канальный типы | Must | Символ с 4 выводами; T4 выполнен для n и p |
| FR-MOS-002 | Модель уровня Shichman-Hodges с учётом эффекта тела (body effect) | Must | T4: сверка с ручным расчётом для 3 областей, допуск 1e-3 |
| FR-MOS-003 | Реализованы области отсечки, линейная и насыщения | Must | T4: для каждой области точка сравнена с ручным расчётом, 1e-3 |
| FR-MOS-004 | Переход между областями плавный, без разрывов в Якобиане | Must | FR-DEV-003 на наборе точек, включая точки перехода областей |
| FR-MOS-005 | Учтена канал-модуляция (параметр `LAMBDA`) | Must | T4 в насыщении: наклон выходной характеристики соответствует ручному расчёту с `LAMBDA`, 1e-3 |
| FR-MOS-006 | Инстансные параметры `W`, `L`; модельные `VTO, KP, GAMMA, PHI, LAMBDA, TOX, CGSO, CGDO, CGBO, RD, RS` — ровно этот перечень | Must | Метаданные (FR-DEV-002) содержат ровно 13 имён; лишних/отсутствующих нет |
| FR-MOS-007 | Ёмкости `Cgs, Cgd, Cgb` рассчитываются с разбиением по области, в которой находится прибор | Must | Сумма ёмкостей по областям совпадает с `CGSO/CGDO/CGBO`-расчётом; переход между областями без скачка тока смещения > 1e-3 |
| FR-MOS-008 | Подпороговый ток реализован как минимум экспоненциальной добавкой `ISUB` (без полноценного BSIM) | Should | На `VGS < VTO` ток монотонно убывает и воспроизводит эталон в допуске G |
| FR-MOS-009 | Учтена температурная зависимость подвижности через `.options temp`; иных температурных эффектов не требуется | Should | Прогон при двух температурах даёт различие токов в направлении, предсказанном ручным расчётом |
| NFR-MOS-001 | Не реализуются и не заявляются: BSIM4/PSP, шум, mismatch, NQS, температура сверх `temp`-зависимости mobility | Must | Отсутствие соответствующих параметров и заявлений в `documentation/DeviceModels.md` |

## 4. Мемристор M1 — Yakopcic (ТЗ 9.2)

Терминалы: 2 + опциональный третий узел SV. SV: `x ∈ [0,1]`, начальное `xo`. По умолчанию — модель мемристора.

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-MEM-001 | M1 — модель мемристора по умолчанию | Must | Новый инстанс мемристора без указания модели имеет M1 |
| FR-MEM-002 | Функция проводимости `G(V)` реализована в точности по ТЗ: `0` при `-Vn <= V <= Vp`; `Ap·(exp(V)-exp(Vp))` при `V > Vp`; `-An·(exp(-V)-exp(Vn))` при `V < -Vn` | Must | U: значения на 3 интервалах совпадают с формулой; G: сверка с эталонным subckt |
| FR-MEM-003 | Функция окна/скорости `F(V,x)` реализована по ТЗ: ветвь `exp(-αp·(x-xp))·wp(x)` при `η·V >= 0, x > xp`, ветвь `exp(αn·(x+xn-1))·wn(x)` при `η·V < 0, x < 1-xn`, иначе `1` | Must | U: все три ветви и границы применимости; G: сверка с эталоном |
| FR-MEM-004 | Вспомогательные функции `wp(x) = xp/(1-xp) - x/(1-xp) + 1` и `wn(x) = x/(1-xn)` реализованы как в ТЗ | Must | U: значения в точках `x = xp`, `x = 1-xn`, `x = 0.5` |
| FR-MEM-005 | Уравнение состояния `dx/dt = η·F(V,x)·G(V)` интегрируется как SV | Must | T5: монотонность `x` на полупериоде; G: совпадение траектории `x(t)` с эталоном |
| FR-MEM-006 | ВАХ: `I = a1·x·sinh(b·V)` при `V >= 0`, `I = a2·x·sinh(b·V)` при `V < 0` | Must | T5: пики токов в пределах 5% от эталона; G: совпадение кривой |
| FR-MEM-007 | Параметры ровно: `a1, a2, b, Vp, Vn, Ap, An, xp, xn, alphap, alphan, xo, eta` | Must | Метаданные содержат ровно 13 имён |
| FR-MEM-008 | `x` не выходит за `[0,1]`; ограничение в окне (`x=xp` при росте, `x=1-xn` при спаде) реализуется внутри `F` | Must | T5: `x ∈ [0,1]` на всём ряду; Link T13: без разрывов в SV; в логе нет `W_STATE_CLIP` при штатном прогоне |
| FR-MEM-009 | При `eta = -1` поведение инверсное (рост при отрицательном напряжении) | Must | U: знак `dx/dt` при `V > 0` и `eta = -1` противоположен знаку при `eta = +1` |
| FR-MEM-010 | Порог: при `|V| < Vp` на положительной полуволне и `|V| < Vn` на отрицательной SV не меняется | Must | T6: `Δx < 1e-6` |
| FR-MEM-011 | Петля I–V на `SIN` 1 Гц воспроизводится в форме и масштабе | Must | T5: форма петли качественно, монотонность `x`, пики в пределах 5% от эталона |
| FR-MEM-012 | Опциональный третий узел SV позволяет вывести `x` как узловое напряжение | Should | При включённом третьем терминале напряжение узла равно `x` с точностью 1e-9 |

## 7. Мемтранзистор GEM (ТЗ 9.3)

Терминалы: D, G, S (3). SV: `w ∈ [w_off, w_on]`.

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-MT-001 | Прибор имеет 3 терминала D, G, S | Must | Символ с 3 выводами; инстанс в netlist из 3 узлов |
| FR-MT-002 | Внутреннее состояние `w` является SV и управляется напряжением `vgs` | Must | T7: `w` меняется только при изменении `vgs`; ряд `@Xmt.w` доступен |
| FR-MT-003 | Уравнение состояния `dw/dt` реализовано по ТЗ в трёх режимах: `vgs < v_off` — `a_off·(exp(vgs - v_off) - 1) + β_off·(w_off - w)^s_off`; `v_off <= vgs <= v_on` — `0`; `vgs > v_on` — `a_on·(exp(vgs - v_on) - 1) + β_on·(w - w_on)^s_on` | Must | U: все три режима и их границы; G: сверка с эталоном |
| FR-MT-004 | Реализованы функции «окна монотонности» `g_off(w, vgs)` и `g_on(w, vgs)`, ограничивающие диапазон `w` в зависимости от амплитуды `vgs` | Must | T7: `w` в границах при серии импульсов; при превышении амплитуды `w` не выходит за `[w_off, w_on]` |
| FR-MT-005 | Выходные характеристики `ids(vds, vgs, w)` — нелинейная функция с двумя режимами («линейный»/«насыщение»), зависящая от `R_M(w)` | Must | U: обе ветви `ids`; T7: ступени `ids` после импульсов |
| FR-MT-006 | По умолчанию `R_M(w) = R_on·w/w_on + R_off·(1 - w/w_on)` | Must | U: `w=w_off → R_off`, `w=w_on → R_on` |
| FR-MT-007 | Параметры (минимально обязательные) ровно: `w_on, w_off, k_on, k_off, alpha_on, alpha_off, s_on, s_off, beta_on, beta_off, v_on, v_off, r_on, r_off, mu, w_init` | Must | Метаданные содержат ровно 16 имён |
| FR-MT-008 | `w` ограничено в `[w_off, w_on]`; начальное значение `w_init` | Must | T7: `w` в границах; старт равен `w_init` |
| FR-MT-009 | При недостаточной амплитуде `vgs` (ниже порога) `w` не меняется | Must | U: при `v_off <= vgs <= v_on` `dw/dt` неотличим от 0 |
| FR-MT-010 | «Стробоскопическое» поведение: один импульс `vgs` даёт ожидаемое изменение `w` и `ids` | Must | T7: после каждого из 10 импульсов `w` и `ids` монотонно ступенчато изменяются |
| FR-MT-011 | Терминал G не потребляет постоянного тока; ёмкость `Cgs` допустима как опция | Must | DC-анализ: ток затвора равен 0 с точностью 1e-12; опция `Cgs` не обязательна для прохождения T7 |

## 8. Нейристор N1 — порогово-переключающая (ТЗ 9.4)

Терминалы: 2. SV: `s ∈ [0,1]` + таймер (приложение B).

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-N1-001 | Двухтерминальный прибор с энергозависимым переключением, состояние `s ∈ {HRS, LRS}` | Must | Символ 2 вывода; U: обе состояния достижимы |
| FR-N1-002 | Переход HRS→LRS при `|V| >= V_threshold` (`V_set`) | Must | U: ниже `V_set` перехода нет; на `V_set` переход происходит |
| FR-N1-003 | Переход LRS→HRS при `|V| <= V_hold` (спонтанный возврат, время `τ_relax`) | Must | U: время возврата соответствует `t_relax` в допуске шага интегратора |
| FR-N1-004 | `R = R_off` в HRS, `R = R_on` в LRS | Must | U: сопротивление в установившемся состоянии равно параметру |
| FR-N1-005 | Параметры ровно: `R_on, R_off, V_set, V_hold, t_delay, t_relax, C_par` | Must | Метаданные содержат ровно 7 имён |
| FR-N1-006 | Учтены задержка `t_delay` и паразитная ёмкость `C_par` | Must | U: переключение не ранее `t_delay` после превышения порога; `C_par` влияет на фронт |
| FR-N1-007 | Ступень переключения аппроксимирована гладкой сигмоидой с шириной `V_smooth` (скрыта от пользователя, ширина настраиваема) | Must | Метаданные не содержат `V_smooth`; настройка ширины меняет крутизну перехода, не меняя порог |

## 9. Нейристор N2 — плавная гистерезисная (ТЗ 9.4)

## 10. Требования к обеим моделям нейристора и LIF-нейрону (ТЗ 9.4)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|

### 13.3 Открытые вопросы ТЗ, влияющие на этот блок

П. 17.4 (тепловая подмодель нейристора) и п. 17.5 (уровень MOSFET) напрямую меняют объём FR-N1/N2 и FR-MOS. До их решения приёмка идёт по текущим формулировкам без тепловой подмодели и на уровне Shichman-Hodges.
