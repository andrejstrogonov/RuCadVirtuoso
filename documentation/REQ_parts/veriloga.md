| Поле | Значение |
|---|---|
| Документ | Формализованные требования, часть «Поддержка Verilog-A» |
| Источник | `documentation/TZ_MVP_schematic.md`, разделы 8.1–8.6, 11 (11.1), 12.2 (T9–T11), 13, 17.2–17.3 |
| Область | Импорт `.va`, AST, проверка типов, codegen C++, компиляция MSVC, кэш по SHA-256, ABI и загрузка через ctypes, подмножество языка, семантика `ddt`/`idt`, диагностика |
| Вне области | Ядро MNA и интегратор (п. 7), внутренние переменные как часть решателя (п. 7.3), библиотека приборов (п. 9), UI-раскладка диалога импорта (п. 10), общие NFR и процесс (раздел общей части NFR) |

## 1. Соглашения

### 1.1 Идентификаторы

`FR-<БЛОК>-<NNN>` — функциональное требование, `NFR-<БЛОК>-<NNN>` — нефункциональное.

| Блок | Содержание |
|---|---|
| `VAIMP` | импорт, валидация структуры, AST и проверка типов (ТЗ 8.1 п.1–3) |
| `VACOD` | codegen C++, компиляция `cl.exe`, кэш DLL (ТЗ 8.1 п.4) |
| `VAABI` | ABI, структура описания модели, ctypes-загрузка (ТЗ 8.1 п.5, 8.4) |
| `VAMET` | метаданные модели для символа и формы параметров (ТЗ 8.1 п.6) |
| `VASUB` | поддерживаемое подмножество языка по категориям таблицы п. 8.2 |
| `VANSUP` | не поддерживаемые в MVP конструкции (список п. 8.2, вторая часть) |
| `VASEM` | семантика derivative, операторов и валидация параметров (ТЗ 8.3) |
| `VAEVT` | события `initial_step` / `final_step` / `analysis` (ТЗ 8.5) |
| `VAERR` | поведение при ошибках, по строкам таблицы п. 8.6 |
| `VANFR` | нефункциональные требования блока (ТЗ 11, 13, 14.2) |

### 1.2 Приоритеты (MoSCoW)

| Приоритет | Правило присвоения |
|---|---|
| Must | в ТЗ п. 8 указано «обязательный блок» / «**Обязательно**» / требование сформулировано императивно (§8.3–8.6) |
| Should | требуемое поведение, у которого ТЗ ограничивает детализацию («ограниченно», «альтернатива», «допускается») либо которое не входит в критерии DoD п. 4.3 |
| Could | в ТЗ помечено «опционально» / «если время позволяет» |

Расширение подмножества языка за пределы таблицы п. 8.2 не допускается: каждая конструкция вне списка «Обязательно» обязана диагностироваться (блок `VANSUP`), а не поддерживаться частично.

### 1.3 Уровни тестирования (ТЗ 12.1)

| Метка | Уровень |
|---|---|
| U | Unit — компонентные тесты лексера, парсера, семантики, codegen, загрузчика ABI |
| I | Integration — `import → compile → ctypes → модель в схеме` |
| S | UI smoke — диалог импорта, форма параметров, сообщения в логе |
| P | Производительность/приёмка (ТЗ 4.3, 13) |

Тест-кейсы T9–T11 берутся из ТЗ 12.2 без изменения нумерации; `S2` — сквозной сценарий из ТЗ п. 3. Допуски: `1e-9` — линейная VA-модель против примитива R (T9, ТЗ 12.2); `1e-3` — нелинейная ёмкость с `ddt` против нативной RC (T10, ТЗ 12.2); `1e-6` — Якобиан против центральных разностей `h = 1e-8·max(abs(v), 1)` (ТЗ 7.2); `1e-12` — встроенные функции против эталонной реализации.

Тестовое условие ISTQB: для каждой единицы транслятора требуется минимум один позитивный и один негативный тест-кейс; негативный тест обязан проверять **код и текст** диагностики, а не только факт отказа.

## 2. Импорт, валидация и фронтенд транслятора (ТЗ 8.1)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VAIMP-001 | `.va`-файл принимается через диалог «Import Verilog-A» (файл или каталог); тот же импорт доступен через headless-API без GUI для прогона в CI | Must | Импорт одиночного файла и каталога с ≥2 файлами даёт одинаковый набор зарегистрированных моделей при равном содержимом; headless-вызов возвращает тот же набор, что UI-вызов (ТЗ 8.1 п.1) |
| FR-VAIMP-002 | До трансляции выполняется валидация структуры: ровно один `module` и ровно один блок `analog` | Must | 0 модулей → `VA_NO_MODULE`; 2 модуля → `VA_MULTIPLE_MODULES`; 0 `analog` → `VA_NO_ANALOG`; 2 `analog` → `VA_MULTIPLE_ANALOG`; во всех случаях DLL не создаётся (ТЗ 8.1 п.2) |
| FR-VAIMP-003 | Транслятор строит AST и выполняет проверку типов до генерации кода; ошибка типа или индексации — диагностика с `file:line:col` | Must | Файл с несовместимым присваиванием и с индексом массива за границей даёт диагностику с точной позицией; codegen не запускается (ТЗ 8.1 п.3) |
| FR-VAIMP-004 | Импорт неразрушающ: неуспешный импорт не меняет уже зарегистрированные модели и `.rlib` проекта | Must | После отказа импорта битого `.va` ранее импортированная модель по-прежнему запускается и даёт тот же результат (ТЗ 8.6, 4.3 п.4) |
| FR-VAIMP-005 | Транслятор не зависит от UI и вызывается как сервис с контрактом «исходник + версия транслятора → результат/структурированные ошибки» | Should | Транспилятор исполняется на машине без GUI-сессии; два запуска с одинаковым входом дают идентичный вывод (ТЗ 5.1) |

## 3. Генерация кода и компиляция (ТЗ 8.1 п.4)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VACOD-001 | Транслятор генерирует C++-исходник, компилируемый `cl.exe` (MSVC) в DLL | Must | Эталонный набор VA-моделей (≥5 файлов, включая M3 VTEAM из ТЗ 9.2) компилируется без ручных правок сгенерированного кода |
| FR-VACOD-002 | DLL размещается в `cache/<hash>.dll`; хэш — SHA-256 от содержимого `.va` и версии транслятора | Must | Изменение одного символа меняет hash и имя DLL; рекомпиляция того же содержимого даёт тот же hash |
| FR-VACOD-003 | При изменённом `.va` (hash не совпадает с кэшем) компиляция выполняется автоматически, без участия пользователя и без переоткрытия проекта | Must | Правка `.va` и повторный запуск анализа используют новую DLL; при неизменном файле DLL не перекомпилируется (проверяется по mtime DLL) (ТЗ 8.6) |
| FR-VACOD-004 | `cache/` — кэш, а не артефакт проекта: не попадает в VCS и не требуется для воспроизведения результата | Must | Полное удаление `cache/` и повторный прогон дают идентичный результат (допуск 1e-9) (ТЗ 6.1) |
| FR-VACOD-005 | Компиляция выполняется только для цели Windows x64 / MSVC; иная цепочка не поддерживается и даёт документированную ошибку, а не неопределённое поведение | Must | Попытка сборки не-MSVC компилятором отвергается с диагностикой до запуска компилятора (ТЗ 11.1) |

## 4. ABI и загрузка модели (ТЗ 8.1 п.5, 8.4)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VAABI-001 | DLL экспортирует стабильный `extern "C"` ABI: `va_get_info`, `va_eval_static`, `va_eval_dynamic`, `va_eval_state`, `va_init`, `va_get_error` | Must | Каждый символ резолвится через `ctypes`; отсутствие любого символа → `VA_ABI_SYMBOL_MISSING` с именем символа, без падения |
| FR-VAABI-002 | `va_model_info` содержит `name`, `num_terminals`, `num_params`, `num_internal_states` и массивы дескрипторов портов и параметров | Must | Значения полей и размеры массивов совпадают с объявлениями исходного `.va` (сверка программная) |
| FR-VAABI-003 | `va_eval_static` возвращает `i_el` и плотную `gmat` (n×n, n = число терминалов) с аналитическими производными | Must | `gmat` совпадает с центрально-разностной оценкой `i_el`, точность 1e-6 |
| FR-VAABI-004 | `va_eval_dynamic` возвращает `q_el` и `cmat` с аналитическими производными для динамического вклада | Must | `cmat` совпадает с разностной оценкой `q_el`, точность 1e-6 |
| FR-VAABI-005 | `va_eval_state` вычисляет `dx` внутренних состояний; `va_init` инициализирует состояние по `initial_step` и параметрам модели | Must | Число состояний из `va_model_info` равно числу объявленных начальных значений; после `va_init` состояние равно объявленному (`initial`) |
| FR-VAABI-006 | Все вычисления `i_el`, `q_el`, `dx` выполняются в `double` | Must | Расхождение с `long double`-эталоном для линейной модели не более 1e-15 |
| FR-VAABI-007 | ABI версионируется константой `VA_ABI_VERSION`; при несовпадении версии DLL не загружается | Must | DLL с другой `VA_ABI_VERSION` отвергается с `VA_ABI_VERSION_MISMATCH`, симуляция не стартует, приложение живо |
| FR-VAABI-008 | Ошибка внутри модели возвращается ненулевым кодом и текстом через `va_get_error()` | Must | При делении на ноль / NaN в модели возвращается код ≠ 0 и непустой текст с именем модели |
| FR-VAABI-009 | Загрузка выполняется через `ctypes.CDLL`; описание модели считывается и валидируется (терминалы > 0, размеры массивов, версия ABI) до первого вызова eval | Must | Порядок вызовов: `CDLL` → `va_get_info` → валидация → eval; при некорректном описании eval не вызывается |
| FR-VAABI-010 | DLL загружается только из `cache/` проекта по hash-имени; путь к DLL не принимается из пользовательского ввода | Should | Попытка подсунуть DLL по внешнему пути отвергается диагностикой |
| FR-VAABI-011 | `white_noise(...)` реализуется как стуб: вызов всегда валиден, вклад в результат MVP не вносит | Must | Модель с `white_noise` компилируется и в TRAN даёт тот же результат, что без вызова (точное совпадение при фиксированном seed) |

## 5. Метаданные модели (ТЗ 8.1 п.6)

| ID | Требование | Приоритет | Условие проверки |

## 6. Поддерживаемое подмножество языка (ТЗ 8.2, «Обязательно»)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VASUB-001 | Модуль `module name(port_list); ... endmodule` принимается и транслируется | Must | Эталонный модуль компилируется; `va_model_info.name` совпадает с объявленным именем |
| FR-VASUB-002 | Порты `inout` / `input` / `output`, электрические `electrical` / `wire`; привязка `V(p,n)`, `I(p,n)` | Must | Модель с тремя портами разных направлений даёт `num_terminals = 3`; `V(p,n)` и `I(p,n)` резолвятся для всех объявленных пар терминалов |
| FR-VASUB-003 | Параметры `parameter real` и `parameter integer` со значением по умолчанию и ограничением `from (...)`; параметр без значения по умолчанию отвергается | Must | Параметр без значения по умолчанию даёт диагностику; `from (0:inf)` принимает 1e-30 и отвергает 0 и отрицательное значение (см. FR-VASEM-005) |
| FR-VASUB-004 | Локальные переменные `real`, `integer`; массивы `real name[0:N]` с константным `N` | Must | Модель с массивом из 8 элементов и индексацией циклом даёт ожидаемый результат; `N` не из константы → ошибка трансляции |
| FR-VASUB-005 | Аналоговый блок `analog begin ... end` — единственный | Must | Вклады из `analog`-блока попадают в eval-функции; вклад вне блока не компилируется |
| FR-VASUB-006 | Операторы: присваивание, `if/else`, `case`, `while`, `for`, `repeat`, блок `begin/end`, `+ - * / ** %`, сравнения, логические `&&`, `\|\|`, `!`, тернарный `?:` | Must | Каждый оператор покрыт ≥1 тест-кейсом; модель с нетривиальными `while`/`for`/`repeat` совпадает с аналитическим результатом, допуск 1e-3 |
| FR-VASUB-007 | Встроенные функции: `abs, min, max, sqrt, exp, ln, log10, sin, cos, tan, asin, acos, atan, sinh, cosh, tanh, asinh, acosh, atanh, pow, floor, ceil, limes`, а также `V()`, `I()` | Must | Каждая функция покрыта тест-кейсом (для обратных — на границе области определения); расхождение с эталонной реализацией ≤ 1e-12 |
| FR-VASUB-008 | Преобразования `ddt(expr)`, `ddt(expr, abshdl)`, `idt(expr)`, `idt(expr, ic)`, `ddx(...)` принимаются в допустимых позициях; семантика — FR-VASEM-001…004; `white_noise` — FR-VAABI-011 | Must | Модель, содержащая каждый вызов в допустимой позиции, компилируется; `ddt` с `abshdl` и `idt` с `ic` дают результат с учётом второго аргумента (проверка на линейной цепи, 1e-9) |
| FR-VASUB-009 | Вклады: `I(p,n) <+ expr;`, `V(p,n) <+ expr;`, `I(p,n) <+ ddt(expr);`, `I(p,n) <+ idt(expr);` | Must | Четыре модели (по одной на форму) компилируются и дают ожидаемые `i_el`/`q_el`/`dx`; `V(p,n) <+ …` формирует уравнение ветви, а не ток |
| FR-VASUB-010 | Чтение напряжения и окружения: `V(p,n)`, `$temperature`, `$vt`, `$simparam`, `$param_given`; `$port_connected` — в ограниченном объёме (FR-VANSUP-008) | Must | `$temperature` возвращает 300.15 К по умолчанию и значение `.options temp=` при задании; `$param_given` истинно только для явно переопределённого параметра (ТЗ 7.8) |
| FR-VASUB-011 | Сообщения `$strobe`, `$display`, `$warning`, `$error`, `$fatal` выводятся в консоль/лог приложения с уровнем и именем модели | Must | Каждый из пяти вызовов даёт запись в логе с соответствующим уровнем; `$fatal` останавливает симуляцию с кодом ошибки |

## 7. Не поддерживаемые в MVP конструкции (ТЗ 8.2, вторая часть)

Общее правило: диагностика «not supported in MVP» с именем конструкции и `file:line:col`; DLL не создаётся; частичная трансляция запрещена (FR-VANSUP-011).

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VANSUP-001 | Не поддерживаются и диагностируются: digital-часть Verilog-AMS, `always`, конечные автоматы, `event` | Must | Файл с `always`-блоком отвергается с именем конструкции и позицией |
| FR-VANSUP-002 | Не поддерживаются и диагностируются: `discontinuity()`, `bound_step()`, пользовательские `analog function`, `task`/`function` | Must | Файл с `analog function` отвергается с именем конструкции, DLL не создаётся |
| FR-VANSUP-003 | Не поддерживаются и диагностируются: `laplace_nd`, `laplace_zp`, `zi_*`, `slew`, `transition` | Must | Каждая конструкция даёт отдельную диагностику с именем |
| FR-VANSUP-004 | `$limit` и `$bound_step` — ошибка трансляции; допустима альтернатива в виде предэкспортного хинта параметров `smooth` вне языка модели | Must | Диагностика с именем конструкции; поведение подлежит пересмотру по открытому вопросу ТЗ 17.3, до решения — ошибка |
| FR-VANSUP-005 | Не поддерживаются и диагностируются: `generate`, `genvar`, `analog initial`, `@(cross)`, `@(above)` | Must | Каждая конструкция отвергается диагностикой с позицией |
| FR-VANSUP-006 | Access-функция `I(p,n)` для ветви без источника не поддерживается; `I(<source>)` поддерживается; `ddt(V(p,n))` разрешено | Must | `I(p,n)` для ветви без источника → диагностика с указанием узлов; `I(<source>)` работает; `ddt(V(p,n))` компилируется |
| FR-VANSUP-007 | `V(p,n)` с собственными производными по времени сверх `ddt(V)` не поддерживается | Must | Попытка построить старшую производную напряжения даёт диагностику |
| FR-VANSUP-008 | `$port_connected` поддерживается в ограниченном объёме, документированном в `documentation/VerilogA_Subset.md`; вне ограничения — диагностика | Should | Для документированных случаев результат соответствует спецификации; для недокументированных — ошибка, а не молчаливый `false` (ТЗ 14.2) |
| FR-VANSUP-009 | `$random`, `$dist_*` не поддерживаются и диагностируются | Must | Оба вызова отвергаются с именем функции |
| FR-VANSUP-010 | Любая конструкция вне подмножества даёт сообщение «not supported in MVP» с именем конструкции и позицией | Must | Для всех конструкций FR-VANSUP-001…009 и FR-VASUB-003/004 текст содержит формулировку «not supported in MVP», имя конструкции и `file:line:col` |
| FR-VANSUP-011 | Отсутствие частичной поддержки: модель либо транслируется целиком, либо отвергается | Must | Ни в одном негативном кейсе не создаётся DLL и не регистрируется модель-полуфабрикат |

## 8. Семантика derivative и операторов (ТЗ 8.3)

| ID | Требование | Приоритет | Условие проверки |
|---|---|---|---|
| FR-VASEM-001 | `ddt(expr)` внутри `I(p,n) <+ ...` засчитывается в `q`: вклад попадает в `va_eval_dynamic`, а не в `va_eval_static` | Must | Модель `I(p,n) <+ ddt(C*V(p,n))` даёт `i_el = 0` в `va_eval_static` и `q_el = C·V` в `va_eval_dynamic` |
