## 1. Правила чтения требований

**Структура записи требования.** Каждое требование — блок из пяти полей:

| Поле | Смысл |
|---|---|
| ID | `FR-<блок>-<NNN>` для функциональных, `NFR-<категория>-<NNN>` для нефункциональных |
| Приоритет | MoSCoW: `Must` / `Should` / `Could`. `Could` — только там, где ТЗ явно пишет «опционально» |
| Формулировка | Проверяемое утверждение о наблюдаемом поведении; без слов «быстро», «удобно», «корректно» без метрики |
| Условие проверки | Измеримое условие приёмки (что сравнивается, с какой точностью, что наблюдается) |
| Трассировка | Пункт ТЗ → тест-кейсы п. 12.2 / сценарии п. 3 / этап п. 15.1 |

**Правила.**
1. Одно требование — одно проверяемое свойство. Если в пункте ТЗ два независимых свойства, они разведены на два ID.
2. Требование не выходит за ТЗ. Всё, что ТЗ оставляет неопределённым, вынесено в раздел 6 «Открытые вопросы» со ссылкой на п. 17 ТЗ и **не** превращено в требование.
3. Точности, допуски и времена берутся из ТЗ буквально: п. 12.2 (критерии тестов), п. 13 (производительность), п. 4.3 (DoD).
4. Диагностические коды (`W_STATE_CLIP`, `W_DC_DISCONTINUITY`, `ConvergenceError`) — часть контракта: код, указание узла/времени и попадание в лог проверяются отдельно от самого поведения.
5. Требования к воспроизводимости численных результатов формулируются как сверка с независимым эталоном (аналитика, ngspice) или как инвариант (монотонность, границы), а не как совпадение с собственной реализацией.

## 2. Функциональные требования

### 2.1 Парсер netlist (`FR-NL`)

**FR-NL-001. Поддержка директив netlist**
- Приоритет: Must
- Формулировка: Парсер распознаёт и обрабатывает директивы `.model`, `.subckt`/`.ends`, `.include`, `.options`, `.ic`, `.param`, `.tran`, `.dc`, `.ac`, `.op`, `.end`.
- Условие проверки: netlist, содержащий все девять директив (и `.end`), разбирается без ошибок; каждая директива попадает в структурное представление схемы с типом и параметрами. Netlist без `.end` — ошибка парсера с ненулевым кодом.
- Трассировка: ТЗ 6.2 → T1, T12 → E0.

**FR-NL-002. Продолжение строк и комментарии**
- Приоритет: Must
- Формулировка: Строка, начинающаяся с `+`, продолжает предыдущую логическую строку; `*` в начале строки и `;` в любом месте строки начинают комментарий.
- Условие проверки: netlist, в котором один оператор разбит на 3 физические строки через `+`, даёт то же структурное представление, что и записанный в одну строку (поэлементное сравнение); текст после `;` не влияет на разбор.
- Трассировка: ТЗ 6.2 → T12 → E0.

**FR-NL-003. Регистронезависимость и эквивалентность узлов `0`/`gnd`**
- Приоритет: Must
- Формулировка: Ключевые слова директив и имена узлов регистронезависимы; узел `0` и узел `gnd` — один и тот же узел земли.
- Условие проверки: два netlist, отличающиеся только регистром (`.TRAN`/`.tran`, `N1`/`n1`) и записью земли (`0`/`GND`/`gnd`), дают идентичное число узлов, идентичную топологию и совпадающий OP (различие ≤ 1e-12 по абсолютной величине).
- Трассировка: ТЗ 6.2 → T1, T12 → E0.

**FR-NL-004. Допустимые имена узлов и иерархические имена**
- Приоритет: Must
- Формулировка: Имя узла состоит из букв, цифр, `_`, `#`, `.`; иерархическое имя вида `X1.N3` сохраняется как путь узла при разворачивании.
- Условие проверки: схема с subckt-инстансом `X1` после разворачивания имеет узлы с именами, содержащими `X1.`; имя узла с недопустимым символом (например, `n$1`) даёт ошибку парсера с `line`/`column`.
- Трассировка: ТЗ 6.2 → T12 → E0.

**FR-NL-005. Множители величин**
- Приоритет: Must
- Формулировка: Числовые величины принимают суффиксы `f p n u m k meg g t` и экспоненциальную запись (`1e-9`); суффикс множителя нечувствителен к регистру.
- Условие проверки: таблица значений `1f 1p 1n 1u 1m 1k 1meg 1g 1t` и `1.5e-9` разбирается в ожидаемые числа СИ с относительной погрешностью ≤ 1e-12; `1M` и `1m` дают одинаковый результат (милли); `1meg` ≠ `1m`.
- Трассировка: ТЗ 6.2, 7.8 → T1, T2 → E0.

**FR-NL-006. Структурные ошибки парсера**
- Приоритет: Must
- Формулировка: Ошибка разбора возвращается структурно, с полями `file`, `line`, `column`, `code`, `message`, и содержит номер строки/позицию ошибочного фрагмента.
- Условие проверки: для набора негативных netlist'ов (неизвестная директива, нечисловое значение величины, незакрытый `.subckt`, отсутствующий `.end`, ссылка на несуществующий subckt) возвращается ошибка с непустыми `file`, `line` > 0, `column` > 0, `code` и `message`; строка указывает на дефектный фрагмент, а не на начало файла.
- Трассировка: ТЗ 6.2 → T11 (механика сообщения), T15 → E0.

**FR-NL-007. Ошибка парсера блокирует симуляцию, но не проект**
- Приоритет: Must
- Формулировка: При наличии ошибки парсера анализ не запускается; проект (его файлы) остаётся валидным и открываемым.
- Условие проверки: после неудачного разбора netlist дальнейший вызов симуляции возвращает ошибку с кодом парсера без запуска решателя (счётчик итераций/вызовов решателя = 0); повторное открытие проекта и успешный разбор исправленного netlist проходят без пересоздания проекта.
- Трассировка: ТЗ 6.2 → T11 → E0.

**FR-NL-008. `.param`-выражения**
- Приоритет: Must
- Формулировка: `.param` поддерживает арифметику `+ - * / ( ) , **` и функции `sqrt exp ln log sin cos tanh min max abs pow` над числами и ранее объявленными параметрами; параметры подставляются в значения инстансов.
- Условие проверки: netlist с цепочкой `.param` (параметр через параметр, все перечисленные функции и операторы, включая `**` и `min/max`) даёт численные значения, совпадающие с независимым расчётом с относительной погрешностью ≤ 1e-12; обращение к необъявленному параметру — ошибка парсера по FR-NL-006.
- Трассировка: ТЗ 6.2 → T1, T12 → E0.

**FR-NL-009. Иерархия subckt: рекурсивное разворачивание**
- Приоритет: Must
- Формулировка: Инстанс `X<name> <nodes...> <subckt> [param=val ...]` разворачивается рекурсивно, с сохранением пути узла и переопределением параметров на уровне инстанса.
- Условие проверки: иерархия из 3 уровней (T12) даёт результаты, идентичные эквивалентной плоской схеме: OP — расхождение ≤ 1e-12, TRAN — расхождение рядов в пределах `reltol=1e-3, abstol=1e-9`; параметр, переопределённый на инстансе, применяется только внутри этого инстанса (проверяется по значению параметра в двух инстансах одного subckt).
- Трассировка: ТЗ 6.2 → T12 → E0.

**FR-NL-010. Рекурсивные/циклические ссылки subckt**
- Приоритет: Must
- Формулировка: Циклическое определение subckt (прямое или косвенное) диагностируется как ошибка парсера, а не приводит к неограниченному разворачиванию.
- Условие проверки: netlist с `A`→`B`→`A` завершает разбор ошибкой FR-NL-006 за конечное время (замер ≤ 1 с, без роста памяти), приложение остаётся работоспособным.
- Трассировка: ТЗ 6.2, 4.3(4) → E0.

**FR-NL-011. Импорт/экспорт netlist как контракт совместимости**
- Приоритет: Must
- Формулировка: Схема экспортируется в текстовый SPICE-совместимый netlist и импортируется обратно без потери топологии, имён узлов, параметров инстансов и списка анализов.
- Условие проверки: «экспорт → импорт → экспорт» даёт побайтно идентичный (после нормализации пробелов/переводов строк) второй и третий экспорт; импортированный netlist даёт OP, совпадающий с исходным до 1e-12.
- Трассировка: ТЗ 6.2, 17(1) → S4 → E0.

**FR-NL-012. Задание температуры через netlist/`.options`**
- Приоритет: Must
- Формулировка: Температура задаётся глобально через `.options temp=` и читается моделями как `$temperature`/`TEMP` в Кельвинах.
- Условие проверки: при `.options temp=350` значение, полученное моделью ($temperature), равно 350 К (проверка через вывод параметра/логирование); без директивы — 300.15 К по FR-UNIT-003; некорректное значение `temp` (нечисло, отрицательное) — ошибка парсера по FR-NL-006.
- Трассировка: ТЗ 7.8 → T1 → E0.

### 2.2 Построение системы MNA + DAE (`FR-MNA`)

**FR-MNA-001. Форма уравнений charge/flux**
- Приоритет: Must
- Формулировка: Ядро формирует систему в форме `f(x) = d/dt q(x) + i(x) + u = 0`, где `x` — узловые напряжения и токи через источники напряжения/индуктивности, `q(x)` — заряды/потоки, `i(x)` — резистивные токи, `u` — вклад независимых источников.
- Условие проверки: на RC-цепи (T2) решение TRAN совпадает с аналитическим откликом с точностью 1e-3; на цепи с нелинейной ёмкостью Verilog-A (T10) — с нативной RC-эквивалентом в пределах 1e-3; размерность вектора `x` равна (число неизвестных узлов + число источников напряжения + число индуктивностей) и проверяется тестом на структуре.
- Трассировка: ТЗ 7.1 → T1, T2, T10 → E0.

**FR-MNA-002. Однократная сборка разреженной структуры**
- Приоритет: Must
- Формулировка: Разреженная структура (CSR) матриц собирается один раз на этапе компиляции схемы; на итерациях обновляются только численные значения.
- Условие проверки: инструментальный счётчик сборки структуры за один TRAN-прогон с ≥ 1000 шагов равен 1; индексы структуры (indptr/indices) на шаге 1 и шаге N идентичны.
- Трассировка: ТЗ 7.1(1) → T13 → E0.

**FR-MNA-003. Контракт вклада прибора**
- Приоритет: Must
- Формулировка: Каждый прибор возвращает статический вклад `i_el` и матрицу `G = ∂i/∂v`, динамический вклад `q_el` и матрицу `C = ∂q/∂v`; вклад шума в MVP не используется; вклад внутренних переменных — по FR-SV.
- Условие проверки: для каждого встроенного прибора (библиотека приборов — вне области этого документа) тест сборки проверяет наличие всех четырёх величин и их размерности (`G`, `C` — `n×n` по числу терминалов); сумма вкладов двух приборов на общем узле даёт аддитивную сборку (сравнение с ручной сборкой, ≤ 1e-12).
- Трассировка: ТЗ 7.1(2) → T1, T4 → E1.

**FR-MNA-004. Диагностика отсутствия DC-пути к земле**
- Приоритет: Must
- Формулировка: Перед решением проверяется, что каждый узел имеет хотя бы одно DC-соединение к земле; нарушение диагностируется до запуска решателя.
- Условие проверки: схема с изолированным узлом (конденсатор в последовательной ветви без резистивного пути) даёт ошибку с именем висящего узла, `ConvergenceError`/счётчик итераций решателя не инкрементируется (диагностика раньше решения).
- Трассировка: ТЗ 7.1(3) → T15 → E0.

**FR-MNA-005. Диагностика висящего вывода прибора**
- Приоритет: Must
- Формулировка: Вывод прибора, не подключённый ни к одному узлу/узлу-заглушке, диагностируется до решения с указанием прибора и вывода.
- Условие проверки: netlist с неприсоединённым выводом мемристора возвращает ошибку, в сообщении присутствуют имя инстанса и номер/имя вывода; решатель не запускается.
- Трассировка: ТЗ 7.1(3) → T15 → E0.

**FR-MNA-006. Диагностика контура источников напряжения/индуктивностей**
- Приоритет: Must
- Формулировка: Контур, состоящий только из источников напряжения и индуктивностей (включая замыкание источника на себя), диагностируется до решения.
- Условие проверки: схема `V1` и `V2`, включённые параллельно между одними узлами, даёт ошибку с кодом диагностики контура; схема без контура (каскад источников через резисторы) ошибки не даёт.
- Трассировка: ТЗ 7.1(3) → T15 → E0.

**FR-MNA-007. `gmin`-шунтирование**
- Приоритет: Must
- Формулировка: Каждый узел шунтируется проводимостью `gmin` к земле, значение по умолчанию 1e-12 См, переопределяется через `.options gmin=`.
- Условие проверки: при `.options gmin=1e-12` OP цепи с узлом, соединённым только через ёмкость, сходится (система невырождена) и даёт напряжение, предсказуемое делителем `gmin`; изменение `gmin` на порядок меняет результат в предсказанном направлении; значение по умолчанию применяется без директивы (проверка через лог/диагностику эффективных опций).
- Трассировка: ТЗ 7.1(4) → T15 → E0.

**FR-MNA-008. Линеаризация разреженной системы**
- Приоритет: Must
- Формулировка: Решение линейной системы на итерации Ньютона выполняется разреженным решателем SciPy `splu` (или `spsolve`); замена на KLU допускается только с обоснованием по производительности.
- Условие проверки: для схемы ≥ 1000 узлов решение линейной системы совпадает с плотным эталоном (`numpy.linalg.solve` на подвыборке ≤ 200 узлов или с `scipy.sparse.linalg.spsolve`) с невязкой ≤ 1e-9; тест фиксирует используемый решатель и падает при молчаливой смене.
- Трассировка: ТЗ 7.4(5) → T13 → E1.

**FR-MNA-009. Непрерывность Якобиана на границах областей (ядерный уровень)**
- Приоритет: Must
- Формулировка: Ядро не вносит разрывов в матрицы `G`/`C` при переходе между областями модели: сборка использует значения, возвращённые прибором, без дополнительного «обрезания» матриц.
- Условие проверки: для тестовой модели, чей Якобиан на границе области внутри прибора гладок, собранная матрица в точках по обе стороны границы различается не более чем на величину, заданную моделью (сравнение собранных `G` на сетке по напряжению, ≤ 1e-9 относительного скачка).
- Трассировка: ТЗ 7.1(2), 9.1 → T4 → E1.

**FR-MNA-010. Устойчивость к нечисловым значениям вклада прибора**
- Приоритет: Must
- Формулировка: Если прибор вернул `NaN`/`Inf` во вкладе, ядро завершает анализ контролируемой ошибкой с указанием инстанса и анализа, а не распространяет нечисловые значения в результат.
- Условие проверки: тестовая модель, возвращающая `NaN` при заданном напряжении, даёт ошибку с именем инстанса; в результирующих рядах нет `NaN`; приложение не падает (FR по устойчивости — NFR-ROB-001).
- Трассировка: ТЗ 4.3(4), 8.6 → T11 → E1.

### 2.3 Якобиан (`FR-JAC`)

**FR-JAC-001. Аналитический Якобиан встроенных моделей**
- Приоритет: Must
- Формулировка: Встроенные модели предоставляют аналитический Якобиан (проверка приборов — вне области этого документа; здесь — механизм проверки и требование к ядру не подменять его разностями).
- Условие проверки: тест сравнивает матрицы `G`/`C`, возвращённые прибором, с центральными конечными разностями и требует совпадения с точностью 1e-6; тест помечен как обязательный для каждой встроенной модели.
- Трассировка: ТЗ 7.2, 12.1(1) → T4, T5, T7 → E1.

**FR-JAC-002. Разностная аппроксимация: формула шага**
- Приоритет: Must
- Формулировка: При разностном fallback используется центральная разность с шагом `h = 1e-8 · max(|v|, 1)`.
- Условие проверки: для аналитически заданной эталонной функции разностный Якобиан ядра совпадает с аналитическим не хуже 1e-6 при `v` из набора {1e-6, 0, 1, 1e3} и `h` строго по формуле (проверяется через инструментированный вызов).
- Трассировка: ТЗ 7.2 → T9, T10 → E2.

**FR-JAC-003. Fallback на конечные разности с предупреждением**
- Приоритет: Must
- Формулировка: Если аналитические производные для модели недоступны (конструкция вне подмножества генератора), ядро переключается на конечные разности и выдаёт предупреждение в лог.
- Условие проверки: прогон с моделью, у которой отключены аналитические производные, завершается успешно, в логе присутствует ровно одно предупреждение о переходе на конечные разности с именем модели; результат совпадает с аналитическим прогоном в пределах допусков п. 12.2.
- Трассировка: ТЗ 7.2 → T9, T10 → E2.

**FR-JAC-004. Аналитический Якобиан предпочтителен**
- Приоритет: Must
- Формулировка: При наличии аналитического Якобиана разностный путь не используется (никаких «пробных» вычислений прибора сверх необходимых).
- Условие проверки: счётчик вызовов `va_eval_static` (или эквивалента) на итерацию равен 1 для модели с аналитическим Якобианом; при fallback — ≥ 1 + 2·n.
- Трассировка: ТЗ 7.2 → T9 → E2.

### 2.4 Внутренние переменные состояния (`FR-SV`)

**FR-SV-001. Произвольное число SV с начальными значениями**
- Приоритет: Must
- Формулировка: Прибор объявляет произвольное количество внутренних переменных `x_i`, каждая с начальным значением `initial`; ядро добавляет их к глобальному вектору неизвестных.
- Условие проверки: для модели с 3 SV вектор неизвестных содержит 3 дополнительных компоненты (проверка размерности); в первой точке TRAN значения SV равны объявленным `initial` (абсолютная погрешность ≤ 1e-12).
- Трассировка: ТЗ 7.3(1) → T5, T7 → E1.

**FR-SV-002. Уравнения невязки для SV**
- Приоритет: Must
- Формулировка: Для каждой SV в систему добавляется уравнение `F_i = dx_i/dt − f_i(x, v) = 0`.
- Условие проверки: модель с известным аналитическим решением `dx/dt = a` при постоянном входе даёт линейный рост `x(t)` с наклоном `a` (относительная погрешность ≤ 1e-3 на сетке TRAN); невязка `F_i` на сошедшемся решении ≤ допусков сходимости FR-SOLVE-002.
- Трассировка: ТЗ 7.3(2) → T5, T7, T8 → E1.

**FR-SV-003. Дискретизация SV той же формулой, что и ёмкости**
- Приоритет: Must
- Формулировка: `dx_i/dt` дискретизируется тем же интегратором, что и заряды (`x` интегрируется как заряд).
- Условие проверки: прогон одной и той же модели SV с интегратором TRAP и BDF1 даёт разные, но соответствующие методам результаты; траектория SV при TRAP совпадает с аналитикой для `dx/dt = const` в пределах 1e-3; тест фиксирует, что метод SV равен методу ёмкостей в отчёте прогона.
- Трассировка: ТЗ 7.3(3), 7.5 → T5, T8 → E1.

**FR-SV-004. `W_STATE_CLIP` при выходе за границы**
- Приоритет: Must
- Формулировка: Ядро не обрезает SV молча; выход за границы `[xmin, xmax]`, ограничение внутри `f_i` которого модель не обеспечила, фиксируется в логе как `W_STATE_CLIP` при включённом режиме отладки.
- Условие проверки: тестовая модель без внутреннего ограничения при входе, выводящем SV за границу, даёт запись `W_STATE_CLIP` с именем инстанса, именем SV, временем и значением; при выключенном режиме отладки запись отсутствует; значения SV в результате не «подрезаны» ядром (значение за границей сохраняется как есть).
- Трассировка: ТЗ 7.3(4) → T5, T6 → E1.

**FR-SV-005. Прямой вывод SV в результаты по имени**
- Приоритет: Must
- Формулировка: SV доступны для вывода в результаты по имени `@<instance>.<sv>` (например, `@Xmem.x`).
- Условие проверки: запрос вывода `@Xmem.x` в спецификации анализа возвращает ряд, длина которого равна числу точек TRAN, и значения которого совпадают со значениями SV из отладочного дампа (≤ 1e-12); запрос несуществующей SV даёт ошибку с перечнем доступных имён.
- Трассировка: ТЗ 7.3(5) → T5, T8 → E1.

### 2.5 Решатель нелинейной системы (`FR-SOLVE`)

**FR-SOLVE-001. Метод Ньютона–Рафсона с обновлением матрицы**
- Приоритет: Must
- Формулировка: Нелинейная система решается методом Ньютона–Рафсона; при расходимости Якобиан пересобирается (модифицированная матрица не «замораживается» навсегда).
- Условие проверки: на тестовой нелинейной цепи сходимость достигается за ≤ 100 итераций; в сценарии с искусственно испорченным первым приближением прогон сходится, и в логе видно ≥ 1 повторную сборку Якобиана.
- Трассировка: ТЗ 7.4(1) → T1, T4 → E0.

**FR-SOLVE-002. Критерий сходимости**
- Приоритет: Must
- Формулировка: Сходимость определяется как `|Δx| < reltol·|x| + abstol` по напряжениям (`vntol`, по умолчанию 1e-6 В) и `abstol` по токам; значения по умолчанию `reltol=1e-4`, `abstol=1e-12`.
- Условие проверки: параметры по умолчанию применяются без `.options` (проверка эффективных опций в отчёте прогона); при ужесточении `reltol` до 1e-8 число итераций растёт и решение уточняется в предсказанном направлении; на эталонной линейной цепи DC-решение совпадает с аналитикой (T1) с точностью 1e-12.
- Трассировка: ТЗ 7.4(2) → T1 → E0.

**FR-SOLVE-003. `ConvergenceError` с указанием узла наибольшей невязки**
- Приоритет: Must
- Формулировка: При недостижении сходимости за 100 итераций выдаётся `ConvergenceError`, содержащий имя узла с наибольшей невязкой.
- Условие проверки: заведомо расходящаяся цепь даёт `ConvergenceError` ровно после 100 итераций, с непустым именем узла; имя узла совпадает с узлом, определённым независимым расчётом невязки (сверка в тесте).
- Трассировка: ТЗ 7.4(3) → T11, T15 → E0.

**FR-SOLVE-004. Стратегии устойчивости в заданном порядке**
- Приоритет: Must
- Формулировка: Стратегии применяются последовательно: `gmin`-stepping → демпфирование шага → `source stepping` (для DC) → `pseudo-transient` (последний резерв для DC и OP).
- Условие проверки: инструментированный прогон на цепи, расходящейся без стратегий, показывает в логе последовательность применённых стратегий в указанном порядке (без перестановок и без пропуска промежуточной стратегии); итоговый прогон завершается успешно.
- Трассировка: ТЗ 7.4(4) → T1, T13 → E1.

**FR-SOLVE-005. `gmin`-stepping**
- Приоритет: Must
- Формулировка: `gmin`-stepping постепенно уменьшает шунт до целевого `gmin` и использует предыдущее решение как начальное приближение.
- Условие проверки: на цепи, где прямое решение расходится, `gmin`-stepping даёт сходимость; в логе видны ≥ 2 ступени с уменьшающимся `gmin`, финальная ступень равна целевому значению `gmin` (≤ 1e-12 расхождение).
- Трассировка: ТЗ 7.4(4) → T13 → E1.

**FR-SOLVE-006. Демпфирование шага**
- Приоритет: Must
- Формулировка: При расходимости шаг демпфируется как `dV = λ·Δx` с уменьшением `λ` с 1.0 до 0.1.
- Условие проверки: на тестовой цепи, где недемпфированный Ньютон расходится, прогон сходится; в логе фиксируются значения `λ` в диапазоне [0.1, 1.0] и момент первого уменьшения; при стабильной цепи `λ` остаётся 1.0.
- Трассировка: ТЗ 7.4(4) → T4 → E1.

**FR-SOLVE-007. `source stepping` для DC**
- Приоритет: Must
- Формулировка: Для DC-анализа применяется `source stepping` (постепенное увеличение источников) как стратегия повышения устойчивости.
- Условие проверки: DC-развёртка цепи с сильной нелинейностью сходится при включённом `source stepping`; в логе видны шаги нарастания источника (≥ 2); стратегия не применяется в AC и не заменяет OP-стратегии.
- Трассировка: ТЗ 7.4(4), 7.6 → T4, T13 → E1.

**FR-SOLVE-008. `pseudo-transient` как последний резерв**
- Приоритет: Must
- Формулировка: При исчерпании прочих стратегий для DC/OP выполняется переход на псевдопереходный анализ; результат помечается как полученный этим путём.
- Условие проверки: специально построенная цепь, сходящаяся только псевдопереходным методом, даёт решение OP; в логе присутствует пометка об использовании `pseudo-transient` и она появляется после записей о `gmin`-stepping/демпфировании/source stepping; для TRAN стратегия не задействуется.
- Трассировка: ТЗ 7.4(4) → T13 → E1.

### 2.6 Интегрирование по времени (`FR-TRAN`)

**FR-TRAN-001. Обязательный BDF1**
- Приоритет: Must
- Формулировка: Поддерживается метод Backward Euler (BDF1), используемый для старта интегрирования и как резерв при неудаче основного метода.
- Условие проверки: принудительный выбор BDF1 на RC-цепи (T2) даёт решение, совпадающее с аналитическим в пределах 1e-3; первый шаг любого TRAN выполняется BDF1 (проверка в отчёте прогона).
- Трассировка: ТЗ 7.5(1) → T2 → E0.

**FR-TRAN-002. TRAP по умолчанию**
- Приоритет: Must
- Формулировка: Метод трапеций (TRAP) используется по умолчанию.
- Условие проверки: TRAN без явного выбора метода отчитывается о TRAP; на RLC-контуре TRAN-результат согласуется с AC-резонансом по частоте ±1% (сверка T3-подобной цепи во временной области).
- Трассировка: ТЗ 7.5(1) → T2, T3 → E0.

**FR-TRAN-003. BDF2 (опционально)**
- Приоритет: Could
- Формулировка: BDF2 реализуется, если TRAP даёт звон при переключениях; достаточно пары TRAP + контроль шага.
- Условие проверки: если BDF2 реализован — тест на переключающей цепи показывает отсутствие звона (монотонность фронта) и совпадение с TRAP в пределах допусков п. 12.2; если не реализован — выбор BDF2 возвращает явную ошибку «не поддерживается» без падения. Требование не входит в критерий DoD.
- Трассировка: ТЗ 7.5(1) → T2 → E1.

**FR-TRAN-004. Точное попадание в точки разрыва**
- Приоритет: Must
- Формулировка: Источники `PULSE`/`PWL` объявляют точки разрыва; интегратор попадает точно в эти точки и не «перепрыгивает» фронт.
- Условие проверки: для PULSE-источника шаг, содержащий фронт, заканчивается в точке фронта с отклонением ≤ 1e-12 с (T14); в ряду результатов присутствует точка, равная моменту фронта.
- Трассировка: ТЗ 7.5(3) → T14 → E0.

**FR-TRAN-005. Управление шагом через LTE, `maxstep` по умолчанию**
- Приоритет: Must
- Формулировка: Шаг управляется локальной оценкой погрешности (LTE) по встроенной производной с учётом `reltol`/`abstol`; `maxstep` жёстко ограничен, по умолчанию `(tstop − tstart)/100`, и настраивается.
- Условие проверки: без `.options maxstep` ни один шаг прогона не превышает `(tstop − tstart)/100` (проверка по ряду точек); при `maxstep=1e-9` (как в примере ТЗ 6.2) все шаги ≤ 1e-9; ужесточение `reltol` уменьшает средний шаг.
- Трассировка: ТЗ 7.5(2) → T2, T13 → E0.

**FR-TRAN-006. Непрерывное продолжение и интерполируемые ряды**
- Приоритет: Must
- Формулировка: Результат TRAN доступен как интерполируемые ряды по времени с сохранением исходных точек интегрирования.
- Условие проверки: для сохранённого ряда интерполяция в промежуточной точке даёт значение, совпадающее с решением, полученным прогоном с принудительным шагом до этой точки, в пределах `reltol=1e-3, abstol=1e-9`; исходные точки интегрирования присутствуют в ряду без прореживания (монотонность времени и совпадение набора с логом шагов).
- Трассировка: ТЗ 7.5(4) → T2, T13 → E0.

**FR-TRAN-007. Реакция на неудачу сходимости шага**
- Приоритет: Must
- Формулировка: При неудаче сходимости на шаге шаг уменьшается вдвое до `minstep`; при исчерпании — останов анализа с указанием времени и узла.
- Условие проверки: цепь с заведомо недостижимой сходимостью на заданном `minstep` останавливается с ошибкой, содержащей время (в пределах `minstep` от точки отказа) и имя узла; уменьшение шага фиксируется в логе (≥ 2 последовательных делений на 2); прогон не «зависает» (завершается за конечное время теста).
- Трассировка: ТЗ 7.5(5) → T11, T13 → E1.

### 2.7 DC и OP (`FR-DC`)

**FR-DC-001. OP как самостоятельный анализ**
- Приоритет: Must
- Формулировка: `OP` вычисляет рабочую точку схемы как самостоятельный анализ.
- Условие проверки: OP делителя R-R (T1) совпадает с аналитическим расчётом с точностью 1e-12; OP доступен через headless API без GUI (NFR-MNT-001).
- Трассировка: ТЗ 7.6 → T1 → E0.

**FR-DC-002. OP как начальное состояние TRAN (t=0)**
- Приоритет: Must
- Формулировка: Для TRAN рабочая точка вычисляется в `t=0` и служит начальным условием (за вычетом `initial` SV по FR-SV-001).
- Условие проверки: значения всех узловых напряжений в первой точке TRAN совпадают с результатом отдельного OP той же схемы с точностью допусков сходимости; при `initial` SV, отличном от OP-решения, SV стартует с `initial` (проверка `@inst.sv` в первой точке).
- Трассировка: ТЗ 7.6, 7.3(1) → T2, T5 → E0.

**FR-DC-003. DC-sweep по одному параметру**
- Приоритет: Must
- Формулировка: DC-развёртка выполняется по напряжению или току независимого источника с указанием начала, конца и шага.
- Условие проверки: развёртка 1000 точек MOSFET-каскада (п. 13) возвращает ровно 1000 точек в монотонном порядке параметра; на линейной цепи (`V1/R`) ток совпадает с законом Ома с точностью 1e-9 на каждой точке.
- Трассировка: ТЗ 7.6 → T4, T1 → E0.

**FR-DC-004. Вложенная развёртка по двум параметрам**
- Приоритет: Must
- Формулировка: Поддерживается развёртка по двум параметрам, где первый параметр — внешний цикл.
- Условие проверки: результат содержит полную сетку N×M точек; порядок выдачи соответствует внешнему циклу по первому параметру (проверка последовательности значений параметров в ряду); на тестовой цепи с независимыми параметрами сетка совпадает с покомпонентным прогоном (≤ 1e-9).
- Трассировка: ТЗ 7.6 → T1 → E0.

**FR-DC-005. `W_DC_DISCONTINUITY`**
- Приоритет: Must
- Формулировка: При разрыве DC-решения (переключение мемристора) выдаётся предупреждение `W_DC_DISCONTINUITY`.
- Условие проверки: DC-развёртка схемы с мемристором, пересекающая порог переключения, содержит в логе `W_DC_DISCONTINUITY` с указанием точки развёртки/узла; на линейной цепи предупреждения нет (0 записей).
- Трассировка: ТЗ 7.6 → T5, T6 → E1.

### 2.8 AC (`FR-AC`)

**FR-AC-001. Линеаризация в рабочей точке DC**
- Приоритет: Must
- Формулировка: AC-анализ линеаризует схему в найденной рабочей точке DC и строит комплексную систему `(G + jωC)·v = b`.
- Условие проверки: AC-прогон сначала выполняет OP (проверка в отчёте); RLC-контур (T3) даёт резонансную частоту ±1% и добротность ±2% относительно аналитики; смещение рабочей точки (изменение DC-смещения) предсказуемо меняет AC-результат.
- Трассировка: ТЗ 7.7(1) → T3 → E0.

**FR-AC-002. Развёртки `dec`, `oct`, `lin`**
- Приоритет: Must
- Формулировка: Поддерживаются три типа развёртки: `dec`, `oct`, `lin` с указанием числа точек на декаду/октаву или общего числа точек.
- Условие проверки: для каждой развёртки число и значения частот в результате точно соответствуют спецификации (`dec`: N точек/декаду с шагом `10^(k/N)`; `oct`: аналогично по основанию 2; `lin`: равномерный шаг, включая конечные точки); тест проверяет счёт точек для диапазона 1 Гц…1 МГц при N=10.
- Трассировка: ТЗ 7.7(2) → T3 → E0.

**FR-AC-003. Развёртка по параметру (опционально)**
- Приоритет: Could
- Формулировка: Дополнительно к развёртке по частоте поддерживается развёртка по параметру.
- Условие проверки: если реализовано — сетка по параметру соответствует FR-DC-003; если нет — явная ошибка «не поддерживается» без падения. Не входит в DoD.
- Трассировка: ТЗ 7.7(3) → T3 → E2.

**FR-AC-004. Комплексный выход: напряжения и токи**
- Приоритет: Must
- Формулировка: Результат AC — комплексные векторы узловых напряжений и токов приборов.
- Условие проверки: для RC-цепи фаза выходного напряжения на частоте `f = 1/(2πRC)` равна −45° ± 1%, модуль равен 0.707 входного ± 1%; ток через резистор согласован с напряжением по фазе (проверка в пределах 1°).
- Трассировка: ТЗ 7.7(4) → T3 → E0.

**FR-AC-005. Представление модуля/фазы в dB/deg**
- Приоритет: Must
- Формулировка: Модуль и фаза выводятся в dB и градусах соответственно.
- Условие проверки: значение в dB совпадает с `20·log10(|v|)` с точностью 1e-9; фаза — в диапазоне (−180°, 180°] и совпадает с `arg(v)` в градусах (1e-9); преобразование обратимо (dB→линейное) в пределах 1e-9.
- Трассировка: ТЗ 7.7(4) → T3 → E0.

### 2.9 Единицы и температура (`FR-UNIT`)

**FR-UNIT-001. Внутренние единицы СИ**
- Приоритет: Must
- Формулировка: Все внутренние вычисления ведутся в СИ (В, А, Кл, Гн, Ф, Ом, См, А/В, К).
- Условие проверки: OP цепи `V1=1 В`, `R1=1 кОм` даёт ток `1e-3 А` (проверка единиц по величине, ≤ 1e-12 относительной); различия единиц между подсистемами нет — результат одного и того же анализа, полученный через netlist с суффиксами и через СИ-запись, идентичен (≤ 1e-12).
- Трассировка: ТЗ 7.8 → T1 → E0.

**FR-UNIT-002. Применение суффиксов величин в парсере**
- Приоритет: Must
- Формулировка: Суффиксы netlist применяются в парсере — во внутренние величины попадают уже масштабированные значения СИ.
- Условие проверки: netlist с `W=2u L=0.18u` и `.tran 1u 1m` даёт в структурном представлении 2e-6, 1.8e-7, 1e-6, 1e-3 с относительной погрешностью ≤ 1e-12 (проверка без запуска решателя).
- Трассировка: ТЗ 7.8, 6.2 → T1 → E0.

**FR-UNIT-003. Температура по умолчанию 300.15 К**
- Приоритет: Must
- Формулировка: `$temperature` (или `TEMP`) возвращает температуру в Кельвинах; значение по умолчанию 300.15 К, переопределяется `.options temp=`.
- Условие проверки: без директивы значение равно 300.15 К (проверка через вывод/лог); с `.options temp=273.15` — 273.15 К; значение передаётся всем приборам одинаково в одном прогоне.
- Трассировка: ТЗ 7.8 → T1 → E0.

## 3. Нефункциональные требования

### 3.1 Производительность (`NFR-PERF`)

Эталонная конфигурация для всех замеров — п. 13 ТЗ: 8 ядер, 16 ГБ RAM, SSD, Windows 11; конфигурация фиксируется в отчёте о приёмке.

**NFR-PERF-001. OP схемы 100 инстансов**
- Приоритет: Must
- Формулировка: OP схемы из 100 инстансов выполняется не более чем за 0.5 с.
- Условие проверки: замер на эталонной машине, медиана из 5 прогонов (после прогрева) ≤ 0.5 с; тест помечен как performance и запускается на эталонной конфигурации.
- Трассировка: ТЗ 13 → T1 → E1.

**NFR-PERF-002. TRAN кроссбара 16×16, 10 000 точек**
- Приоритет: Must
- Формулировка: TRAN кроссбара 16×16 мемристоров на 10 000 точек выполняется не более чем за 120 с без разрывов в SV.
- Условие проверки: время ≤ 120 с на эталонной машине; в траекториях SV отсутствуют `NaN` и скачки, нарушающие ограничения модели (это же — T13). Требование входит в DoD (п. 4.3(3)).
- Трассировка: ТЗ 13, 4.3(3), 12.2(T13) → T13 → E1.

**NFR-PERF-003. TRAN «мемристор + RC», 100 000 точек**
- Приоритет: Must
- Формулировка: TRAN схемы «один мемристор + RC» на 100 000 точек выполняется не более чем за 60 с.
- Условие проверки: замер на эталонной машине, ≤ 60 с; результат численно корректен (сверка с эталоном по допускам п. 12.2, чтобы оптимизация не достигалась ценой точности).
- Трассировка: ТЗ 13 → T2, T5 → E1.

**NFR-PERF-004. DC-sweep 1000 точек, MOSFET-каскад**
- Приоритет: Must
- Формулировка: DC-развёртка 1000 точек MOSFET-каскада из 10 транзисторов выполняется не более чем за 10 с.
- Условие проверки: замер на эталонной машине, ≤ 10 с; стратегии устойчивости (FR-SOLVE-004) могут быть задействованы, но не более одного раза на точку развёртки (проверка по логу).
- Трассировка: ТЗ 13 → T4, T13 → E1.

**NFR-PERF-005. Масштабирование по размеру схемы**
- Приоритет: Should
- Формулировка: Время OP и одной итерации Ньютона растёт не быстрее чем линейно по числу неизвестных при сохранении разреженности (следствие сборки CSR однократно и `splu`).
- Условие проверки: замеры на цепочках RC из 100/400/1600 узлов: отношение «время на узел» для 1600 узлов не превышает 3× от значения для 100 узлов.
- Трассировка: ТЗ 7.1(1), 7.4(5), 16 (риск «Производительность Python на кроссбарах») → T13 → E1.

**NFR-PERF-006. Память для схемы до 1000 инстансов**
- Приоритет: Must
- Формулировка: Схема до 1000 инстансов обрабатывается при потреблении не более 1 ГБ RAM.
- Условие проверки: пиковое RSS процесса ядра при OP+DС/TRAN на схеме 1000 инстансов ≤ 1 ГБ (замер без GUI, headless).
- Трассировка: ТЗ 11 → T13 → E1.

### 3.2 Устойчивость и обработка ошибок (`NFR-ROB`)

**NFR-ROB-001. Ни одна ошибка ввода/модели не приводит к падению**
- Приоритет: Must
- Формулировка: Ошибки пользовательского netlist'а и ошибки моделей (включая исключения на границе DLL и `NaN`/`Inf`) перехватываются в ядре и возвращаются как контролируемые ошибки; приложение остаётся работоспособным.
- Условие проверки: набор из ≥ 15 дефектных входов (синтаксис, пропущенный `.end`, цикл subckt, неизвестный прибор, `NaN` в модели, расходимость, разрыв на `minstep`) не вызывает аварийного завершения процесса; после каждой ошибки следующий корректный прогон проходит успешно в том же процессе.
- Трассировка: ТЗ 4.3(4), 11 → T11, T15 → E0.

**NFR-ROB-002. Локализация и содержание сообщений об ошибках**
- Приоритет: Must
- Формулировка: Сообщения симулятора об ошибках выводятся на английском с русской подсказкой; каждое сообщение содержит код, контекст (анализ, инстанс/узел, время) и уровень (info/warning/error).
- Условие проверки: выборка из 10 типовых ошибок ядра: у всех заполнены код, уровень, контекст; английский текст присутствует, русская подсказка присутствует; поиск по коду ошибки в документации даёт результат (соответствие `VerilogA_Subset.md`/`UserGuide_ru.md` — вне области этого документа).
- Трассировка: ТЗ 11 → T11 → E2.

**NFR-ROB-003. Диагностика до решения**
- Приоритет: Must
- Формулировка: Топологические дефекты (висящий узел/вывод, контур источников) выявляются до запуска численного решения и до расходования времени на итерации.
- Условие проверки: для дефектной схемы время до ошибки ≤ 10 мс и счётчик итераций решателя = 0 (механически проверяется инструментированием).
- Трассировка: ТЗ 7.1(3) → T15 → E0.

**NFR-ROB-004. Отсутствие «тихих» подмен результата**
- Приоритет: Must
- Формулировка: Ядро не подменяет численные значения, не обрезает SV и не подменяет метод интегрирования без записи в лог.
- Условие проверки: аудит всех мест изменения значений в ядре тестом-«канарейкой»: при вынужденных модификациях (демпфирование, fallback Якобиана, смена стратегии, `pseudo-transient`) в логе присутствует соответствующая запись; на «чистом» прогоне линейной цепи число таких записей = 0.
- Трассировка: ТЗ 7.3(4), 7.2 → T2, T11 → E0.

**NFR-ROB-005. Изоляция ошибок моделей на границе вызова**
- Приоритет: Must
- Формулировка: Исключение/аварийный код возврата из загружаемой модели перехватывается на границе вызова DLL и превращается в `VA_RUNTIME_ERROR` (текстовая часть — вне области этого документа; ядро обеспечивает останов без падения).
- Условие проверки: тестовая DLL, возвращающая ненулевой код и текст ошибки, останавливает симуляцию с сообщением, содержащим имена модели и инстанса; процесс жив (после ошибки выполняется успешный прогон).
- Трассировка: ТЗ 8.6, 4.3(4) → T11 → E2.

### 3.3 Численная достоверность (`NFR-ACC`)

**NFR-ACC-001. Допуски сверки с эталонами**
- Приоритет: Must
- Формулировка: Результаты сверяются с эталоном (аналитика/ngspice) с допуском `reltol=1e-3, abstol=1e-9`; для тестов с явно заданной точностью действуют значения п. 12.2 (T1 — 1e-12, T2 — 1e-3, T3 — частота ±1%/добротность ±2%, T4 — 1e-3, T5 — пики токов в пределах 5%).
- Условие проверки: golden-тесты п. 12.1(2) проходят в CI; при провале выдаётся точка максимального расхождения (время/параметр, узел) и оба значения.
- Трассировка: ТЗ 12.1(2), 12.2 → T1–T8 → E0–E1.

**NFR-ACC-002. Отсутствие «подгонки» моделей под тесты**
- Приоритет: Must
- Формулировка: Эталоны хранятся в `tests/golden/` и генерируются независимо (ngspice/референсные subckt); изменение эталона требует отдельного обоснованного изменения, а не подстройки под текущий результат.
- Условие проверки: тест проверяет, что файлы `tests/golden/**` не изменяются в коммитах, меняющих код моделей/ядра, без отдельного маркера в описании изменения; расхождение с эталоном трактуется как дефект кода.
- Трассировка: ТЗ 12.1(2), 16 (риск «Отличие результатов от опубликованных моделей») → T4–T8 → E1.

**NFR-ACC-003. Инварианты решения**
- Приоритет: Must
- Формулировка: Для каждого прогона проверяются инварианты: конечность всех значений, SV в объявленных границах, монотонность времени в рядах TRAN, монотонность `x` мемристора на одном полупериоде (T5).
- Условие проверки: автоматическая проверка инвариантов запускается в каждом integration-тесте; нарушение даёт понятную ошибку с указанием точки и величины.
- Трассировка: ТЗ 12.2 (T5, T13) → T5, T13 → E1.

### 3.4 Воспроизводимость (`NFR-REP`)

**NFR-REP-001. Детерминизм прогона**
- Приоритет: Must
- Формулировка: Один и тот же netlist и спецификация анализа на одной и той же конфигурации дают побитно идентичные результаты при повторных запусках (в том числе в другом процессе/после перезапуска).
- Условие проверки: два последовательных прогона (в разных процессах) дают идентичные массивы результатов (сравнение побитно); отчёт прогона (метод, число шагов, число итераций) идентичен.
- Трассировка: ТЗ 7.5(4), 4.3 → T1, T2, T13 → E0.

**NFR-REP-002. Воспроизводимость на другой машине**
- Приоритет: Must
- Формулировка: Сохранённый результат/проект воспроизводится на другой машине в пределах допусков п. 12.2 (не побитно; расхождения из-за версии BLAS/компилятора допустимы только в пределах допусков).
- Условие проверки: эталонный набор из п. 12.2, прогнанный на двух конфигурациях (эталонная и отличная), проходит по допускам; фиксируется версия numpy/scipy в отчёте.
- Трассировка: ТЗ 2(4), 4.3, 12.1(2) → T1–T8 → E4.

### 3.5 Тестируемость, логи, ресурсы (`NFR-MNT`)

**NFR-MNT-001. Headless API для всех анализов**
- Приоритет: Must
- Формулировка: Все анализы (OP, DC, TRAN, AC) доступны через API `run_analysis(circuit, analysis_spec) -> Result` без запуска GUI; ядро не зависит от UI.
- Условие проверки: тест импортирует ядро без импорта UI-модулей (проверка `sys.modules` после импорта) и выполняет полный цикл T1–T3; запуск возможен в headless CI на Windows.
- Трассировка: ТЗ 5.1, 11 → T1–T3 → E0.

**NFR-MNT-002. Логирование и ротация**
- Приоритет: Must
- Формулировка: Ядро пишет лог с уровнями info/warning/error, включая диагностические коды (`W_STATE_CLIP`, `W_DC_DISCONTINUITY`, стратегии решателя); ротация логов — по правилам п. 11 (файл в `%APPDATA%/RuCadVirtuoso/logs/`).
- Условие проверки: прогон с задействованными диагностиками даёт все ожидаемые записи с временем, кодом, контекстом; при многократном превышении лимита размера создаются ротационные файлы, суммарный объём ограничен настройкой.
- Трассировка: ТЗ 11 → T11, T13 → E4.

**NFR-MNT-003. Ресурсы процесса ядра**
- Приоритет: Should
- Формулировка: Ядро не удерживает память после завершения анализа: результаты освобождаются по завершении прогона, повторные прогоны не приводят к монотонному росту памяти.
- Условие проверки: 50 последовательных прогонов T2 в одном процессе: RSS после 50-го прогона превышает RSS после 5-го не более чем на 10%.
- Трассировка: ТЗ 11 → T2 → E4.

### 3.6 Совместимость формата (`NFR-COM`)

**NFR-COM-001. Совместимость netlist со средствами сверки**
- Приоритет: Must
- Формулировка: Netlist, экспортированный ядром, читается ngspice (для подмножества, используемого в golden-тестах), а netlist из golden-набора — читается парсером ядра.
- Условие проверки: каждый golden-netlist п. 12.1(2) успешно загружается и ngspice, и ядром; расхождение результатов — в пределах NFR-ACC-001; при несовместимости фиксируется список конструкций, требующих нормализации.
- Трассировка: ТЗ 6.2, 12.1(2), 17(1) → T1–T8 → E1.
